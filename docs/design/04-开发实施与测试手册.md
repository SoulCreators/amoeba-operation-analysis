# 开发实施与测试手册

## 1. 工程基线和边界

本仓库是模块化单体：Java 8、Spring Boot 2.7.18、Maven 六模块，PostgreSQL，Vue 3/TypeScript/Vite；API 与 Worker 分进程运行。前端页面目前仍主要由 `WorkbenchPage.vue` 编排。后端数据主线采用 Spring JDBC/JdbcTemplate，文件解析采用 POI；不能因为 POM 声明 MyBatis 就按 Mapper 主线设计。详情见 [现有架构](../architecture/README.md) 与 [本地开发步骤](../development/local-development.md)。

```text
frontend/src/features/        页面与交互；shared/api/ 维护 HTTP、DTO、请求函数
backend/analysis-api/          Controller、请求/响应 DTO、认证边界、异常映射
backend/analysis-application/  用例编排、事务、任务生命周期、权限调用
backend/analysis-domain/       状态、规则、业务不变量和仓储端口
backend/analysis-infrastructure/ JDBC、POI、文件、本地 AI 适配器
backend/analysis-worker/       异步导出、重试、事件投递等后台执行
backend/analysis-common/       真正通用的少量跨模块模型
database/migration/            只追加前向迁移；verification/ 和 rollback/ 是配套资料
templates/import/              导入模板；docs/requirements/ 是业务口径基线
```

Maven 依赖方向保持 `api/worker → infrastructure → application → domain → common`；领域层不依赖 Spring、SQL、POI。新能力先在现有六模块内按 `ingestion/calculation/forecast/configuration/authorization/reporting/audit` 业务包逐步收敛，不为目录外观额外建空模块。API/Worker 不直接互相依赖。跨域通过应用服务/端口交互，禁止页面或 Controller 直接实现财经公式。

## 2. 一项功能从需求到发布的开发流程

1. 在 [追踪矩阵](05-追踪矩阵与待决策事项.md) 认领需求 ID、UAT 和决策状态，确认业务公式、样表、权限范围及责任人；待确认口径只做原型和数据接入，不生成正式金额。
2. 产品提供页面字段、空态、失败态和下钻上下文；财经提供输入样本、控制总额与预计结果。维护字段级模板字典及指标字典，明确金额单位、汇率方向、零值和分摊尾差。
3. 先设计不变量与数据迁移，再实现领域规则和应用编排；所有导入/计算写入应带源版本、配置快照和追踪号。任何新的财务规则先做规则变更单和版本号。
4. 为 API 编写 OpenAPI/DTO 示例，前后端按 `ApiResult`、状态码、幂等、权限和错误语义联调；禁止前端拼出正式 FC、累计、矩阵或 PVM 数字。
5. 使用隔离 PostgreSQL、构造样本和财经黄金样本做规则、数据库契约、服务集成与浏览器验证；通过权限负例与导出回归，再进入财经 UAT。
6. 发布前冻结迁移、模板、规则、服务镜像和前端构建的版本清单，执行备份、迁移、冒烟和回退演练；经财经确认结果版本后开放发布。

每项合并请求应说明：需求/决策编号、受影响数据对象和口径、迁移及回滚方案、测试样本与控制总额、权限变化、监控与部署注意点。评审必须能从一个结果行走回源行、配置、规则、调整和操作者。当前仓库中已有的类或接口只能作为实现起点，不能替代上述验收。

## 3. 本地环境与运行

以 [本地开发文档](../development/local-development.md) 为可执行命令主来源。CI 基线为 JDK 8、Node 20、PostgreSQL 16；Maven/Node 版本以仓库配置及 CI 为准。所有数据库测试在**新建隔离测试库**运行，禁止对生产库执行测试或验证脚本。连接使用 `AMOEBA_DB_URL/USERNAME/PASSWORD` 注入；本地开发身份仅在 `local` Profile 使用，正式环境必须接可信 SSO/网关。

```bash
# 仓库根目录；先配置隔离 PostgreSQL 连接和 JDK 8
source deploy/scripts/env-local.sh
make check
for migration in database/migration/V*.sql; do
  psql -v ON_ERROR_STOP=1 -f "$migration" || exit 1
done
for verification in database/verification/*.sql; do
  psql -v ON_ERROR_STOP=1 -f "$verification" || exit 1
done
mvn -B clean verify
cd frontend
npm ci
npm run test:unit
npm run build
```

上述迁移循环只适用于**空测试库**。既有环境必须维护迁移历史与校验和，按版本增量执行，不能重新运行所有脚本或编辑已执行 SQL。`mvn verify` 的 PostgreSQL 契约测试缺连接时失败属于有效阻断，不跳过后声称通过。API 本地启动与 Playwright 步骤见链接文档。

## 4. 数据库迁移与版本治理

新增 DDL 只追加下一编号 `Vnnn__description.sql`，同一迁移包含结构、约束、索引及必要的数据回填；大表迁移拆成兼容、回填、收敛阶段。迁移评审检查：唯一约束是否涵盖有效版本、未授权范围能否被索引支持、历史结果外键是否阻止误删、回填是否可重复、失败如何恢复、应用新旧版本是否兼容。`database/verification/` 为变更后的结构/数据断言，`rollback/` 仅供应急参考；财经已发布数据的回退优先通过旧应用读旧版本，不能直接删表或覆盖已发布行。

建议建立迁移登记表，记录脚本号、校验和、执行人、环境、起止时间、结果及备份点。生产发布时先备份，再按评审顺序执行迁移、启动 API/Worker、做授权冒烟、发布观察；若失败停止写入与发布，按已验证恢复方案回到同一数据/代码版本。RPO/RTO 尚未由业务给出，不编造承诺值；恢复演练需补测。

## 5. 测试分层与验收样本

| 层 | 必测内容 | 证据形式 |
|---|---|---|
| 规则单测 | 三视角独立损益、零量、特殊业务、费用取舍、精度、分摊守恒、PVM 两座桥、累计分子/分母重算 | 输入样本、预期未舍入数值、规则版本 |
| 导入/DB 契约 | 模板列序、必填/别名、整期覆盖、无效文件回滚、唯一约束、并发、快照血缘、FC 官方版约束 | 隔离 PostgreSQL 运行记录和迁移版本 |
| API 集成 | 状态转移、幂等重放、重复计算、确认/发布阻断、版本历史、错误码、追踪查询 | 请求/响应与结果版本断言 |
| 权限/安全 | 跨视角/范围、未发布、汇总与明细、导出二次鉴权、巴长同型号跨基地、用户失效 | 拒绝响应和零数据泄露断言 |
| 前端/浏览器 | 完整状态、旧响应竞态、无 FC、累计未实现提示、金额/口径标签、下载一致性 | Vitest/Playwright 报告和截图 |
| 性能/恢复 | 10 万行上传异步响应、月度全量计算、汇总导出、备份恢复、Worker 重试 | 数据规模、硬件、耗时分位数、恢复记录 |
| 财经 UAT | V1.3 UAT-001~072，三视角至少各一个代表范围和财经控制总额 | 财经签字、样本版本、差异报告 |

V1.3 第 20.3 节列出基准月、正常/零量/无预算、分摊、特殊业务、双粒度、管理/研发/减值/闲置、海外及未匹配样本。这些是**由财经初始化时提供**的验收样本，现仓库测试数据不能冒充黄金样本。正式金额、累计和 PVM 差异容忍度为 0；样本缺失或差异未解释时不得把技术测试通过写作财经验收完成。性能目标：正常网络看板首屏 3 秒、复杂下钻 5 秒、月度全量 30 分钟、常规汇总导出 5 分钟；可用性目标为月结高峰核心功能 99.5%。须在约定硬件与样本规模下测量，目标不是当前实测值。

## 6. CI 与发布门禁

现有 CI 和 `make check` 校验模块/目录边界、构建及测试；发布流水线还须加入：迁移校验和与空库升级测试、数据库契约零跳过、前端构建、关键权限负例、依赖/制品扫描、OpenAPI 向后兼容检查、财经样本回归与审计字段检查。生成产物记录 git commit、迁移最高版本、模板/规则版本、镜像摘要及测试报告。生产发布需要可信身份接线、密钥配置、文件存储、备份恢复和网络隔离通过检查。普通计算版本快照未贯通、真实财经样本未通过、生产 SSO 未接入时，不应把本设计或现有测试作为上线证明。

## 7. 可观测性、运行手册与故障处置

每条上传/解析/计算/导出/AI 链路统一 `traceId`，指标至少有成功率、等待/运行时间、超时、积压量、阻断问题数、勾稽差异、未匹配金额、任务重试次数、导出过期清理和 Outbox 投递延迟。日志记录任务阶段与数量，不记录完整财务原文。告警应包含任务号、期间、视角、阶段、错误码和处置入口，不在通知正文携带敏感经营数字。

运维处置顺序：按追踪号确认任务与输入版本 → 区分数据/口径/权限/技术错误 → 数据错由财经重传或改配置并重算，技术错在同一输入快照上安全重试 → 复核勾稽和版本状态 → 由财经确认发布。禁止在生产数据库直接修改正式结果。定期演练：源文件和数据库一致性备份、版本恢复、Worker 中断续跑、发布撤回、旧版追溯、用户失效及导出链接失效。现有 [部署文档](../operation/部署文档.md) 可作为操作入口，具体生产参数和 RPO/RTO 待基础设施/业务共同确认。

## 8. 交付完成定义

某能力“完成”需同时具备：批准的口径与字段/原型、实现及迁移、API 契约、角色和范围检查、审计/血缘、自动化规则与权限测试、隔离库验证、财经黄金样本 UAT、运维与回滚说明、交付版本记录。对口径待确认项可标记“原型/基础接入完成”，不可标“正式计算完成”。一期开工前缺少的字段级模板、完整指标字典、页面原型、接口字段/错误码和追踪矩阵，本套文档已补逻辑设计与追踪框架；具体 Excel 列、财经公式和签字样本仍须由对应责任方补齐。

# 数据模型与计算规则

## 1. 数据契约与分层

源于 V1.3 第 6—13、22 章。以下逻辑模型是**目标设计**，并非当前数据库均已有同名表。物理落库需逐表评审、编写前向迁移并附数据库契约测试。当前库有 `meta/flow/raw/cfg/calc/iam/audit/mart` schema 和部分批次、损益、版本、FC、导出、审计表；表是否存在不表示业务链路已接通。[现有架构](../architecture/README.md) 和迁移文件才是代码现状依据。

| 层 | 写入内容 | 不变量 |
|---|---|---|
| ODS 原始 | 文件哈希、模板编码/版本、Sheet、行号、原字段和值、操作者 | 原始证据只追加；失败文件也保留可诊断记录，受保存策略管理 |
| STD 标准 | 期间、数据对象、业务键、原币/人民币、原始/标准单位、来源行 | 每行必须可回到原行；同一生效文件版本内业务键按对象规则唯一 |
| MAP 归属 | 精确映射结果、特殊业务、费用分类、配置记录 ID、未匹配原因 | 一行一套明确归属；冲突不静默选择首条 |
| CAL 计算 | 分摊链、损益/PVM/指标、调整、校验报告、版本与快照 | 结果绑定输入集合、规则和配置快照；零容差校验未通过不得发布 |
| APP 应用 | 经授权的结果查询、导出快照、AI 上下文 | 仅查持久化版本；范围与层级权限在服务端落实 |

一条正式结果的血缘链设计为 `publication_id → result_version_id → calc_job_id → {source_file_version_ids, config_snapshot_id, rule_version_ids, adjustment_ids} → {std_row_ids, raw_row_ids}`。`trace_id` 是稳定的查询入口；只给有明细权者返回原行。文件哈希用于完整性，不作为业务唯一键。配置不设业务生效期间和独立版本号，**计算快照**承担历史解释能力；公式规则则另有受控版本。已发布结果的快照不可变。

## 2. 实体、唯一约束与状态

| 逻辑实体（建议） | 主键/关键唯一约束 | 必备字段与关系 |
|---|---|---|
| `period` / `batch` | 期间；批次号及期间＋数据集 | 年月、视角/数据集、状态、创建人、关闭标识、乐观锁 |
| `source_file_version` | file_id；期间＋数据对象＋版本号；同对象最多一个生效版本 | 模板、文件哈希、存储地址、行数、校验状态、生效标识、上传人/时间 |
| `raw_row` / `std_row` | 行 ID；文件＋Sheet＋行号；标准业务键需按数据对象判重 | 原始 JSON、标准字段、来源行 ID、数据质量状态、原币金额/汇率/人民币金额 |
| `mapping_entry` / `allocation_entry` / `grain_config` | 各自业务键；有效记录唯一 | 输出归属、比例、有效标识、维护人、乐观锁；基地粒度只能单个有效值 |
| `config_snapshot` | snapshot_id；内容哈希 | 计算任务、映射/费用/汇率/分摊/粒度/指标字典的确定性序列化内容 |
| `calc_job` / `result_version` | 任务 ID；期间＋视角＋递增版本号 | 输入集合哈希、快照、规则版本、状态、阶段、心跳、发起人、发布人/时间 |
| `metric_result` / `pvm_result` | 版本＋视角＋正式粒度＋指标/因素＋当期累计＋场景 | 未舍入金额、分子、分母、单位、特殊业务、trace_id、校验状态 |
| `allocation_trace` / `adjustment` | 链路 ID / 调整 ID | 原费用→基地→线体→接收对象及比例；调整依据、正负、有效状态 |
| `issue` / `audit_event` | 事件 ID；追踪号 | 错误码、级别、源定位、处置人/时间/原因；前后值摘要、终端、结果 |
| `fc_version` / `fc_snapshot` | 版本码；同基准月＋范围最多一个正式采用版 | 基准月、覆盖期、状态、上传/发布人、场景、来源及完整性 |
| `nonfinancial_fact` / `nonfinancial_result` | 期间＋基地＋拉线＋型号＋类目＋目标/实际＋有效文件版本 | 原比例、巴长工号、目标/实际、配对状态、结果版本、源行 |
| `user_scope` / `publication` / `ai_analysis` | 工号＋角色＋视角＋范围；发布 ID；AI 版本 ID | 层级/操作权限、结果可见范围、AI 模型和提示词版本 |

设计建议：用部分唯一索引保证“单个生效文件”“单个正式 FC”“单个有效基地粒度”；事务内切换生效指针，保留旧行。物理删除只允许受控保留期清理，不得级联删除已发布版本的血缘。`period` 可用 `YYYY-MM`，但跨库统一用日期/年月规范；时间存储使用统一时区，页面按公司时间显示。金额和比例用 `NUMERIC`/Java `BigDecimal`，比例至少 8 位小数；金额精度、舍入模式、汇率乘除方向仍需纳入字段字典并经财经确认。不要以二进制浮点做正式运算。

## 3. 数据对象与模板落地

模板登记最小字段：`dataset_code, object_code, template_code, template_version, sheet_code, field_code, label, alias[], type, required_rule, unit, enum, validation, example, status`。导入适配器显式映射列名/编码到标准字段，不按列位置推断。所有数据对象需分别提供字段级 `.xlsx` 模板、样例、枚举及错误定位规则；V1.3 第 7.2 节给出**逻辑字段**，不是已完成的物理模板。模板冻结后将文件和字段字典列入版本清单。

核心标准字段字典草案如下。`DECIMAL` 均为十进制高精度，物理 `NUMERIC(p,s)` 的 `p/s` 需按真实样本最大值和汇率精度评审；“条件必填”必须写入模板的机器可执行校验表达式。实际 Excel 列名/Sheet 名由财经样表映射，不在此凭空指定。

| 字段编码 | 类型/单位 | 必填规则 | 校验与用途 |
|---|---|---|---|
| `period` / `scenario` | `YYYY-MM` / 枚举 | 全对象必填 | 场景 ACT/BGT/FC；预算源保留年度与月度归属 |
| `source_file_id` / `source_sheet` / `source_row_no` | ID/文本/整数 | 系统生成 | 原行唯一定位；结果血缘必需 |
| `shipping_base` / `revenue_base` | 编码 | 基地明细必填 | 后者决定基地视角；`不计算`为合法排除值 |

| `customer_short` / `project_adjusted` / `cell_model` | 标准化文本 | 共用收入成本映射键必填；基地型号可空但需标记 | 去首尾空格/全半角；不做模糊命中 |

标准化需同时保存原值、原单位、换算系数与标准值：实际金额统一人民币元，电量统一 kWh；万元→元和 GWh→kWh 在 STD 转换。海外按期间＋收入计算基地＋原币查财经维护汇率，并保留换算方向；缺汇率阻断。源文件结果字段用于对照，销售成本正式值优先由已确认组成项相加；材料损耗若已在材料成本中，不能重复扣加。

## 4. 配置与归属算法

1. **销售映射**：标准化四字段后精确匹配有效行；0 条输出未匹配，>1 个不同归属输出冲突。基地零售/B品先按`客户项目改`识别并采用特殊粒度；产品线/事业部按`客户简称-改2`统一归 B品。两套识别规则不可复用同一分支。
2. **库存分摊**：按物料编码及归属序号取有效记录，比例合计精确为 1；金额和数量同比分配，尾差处理必须使逐行分配合计等于原值且保留尾差归属记录。尾差规则属于实现设计，需财经确认其展示口径。
3. **费用归属**：基地按公司＋事业部＋三级部门＋OU 基地匹配，失效/空分类排除且记录金额。研发项目直接归属优先，公共项指定接收对象优先于比例。总部费用按总部→基地→线体→产品线/事业部逐级留痕。
4. **基地粒度**：普通业务读取当前基地唯一有效配置，计算快照中固化 `BASE_MODEL` 或 `BASE_MODEL_PROJECT`；特殊业务优先，无型号维度。变更配置只影响未来计算，不回写旧版本。
5. **巴长**：仅按型号从通用销售项目映射提取唯一有效巴长工号；同型号不同基地归同一巴长，基地只用于展示/基地财经权限。多巴长冲突阻断非财经发布。

## 5. 计算 DAG 与版本原子性

`锁定输入/快照 → 标准化/去重 → 映射/特殊业务 → 分摊 → 有效调整 → 三视角独立损益 → 当期/累计/GAP → PVM/专题 → 零容差校验 → 候选版本`。非财经指标独立 DAG，不影响财务结果。每个阶段记录行数、金额控制数、开始/结束时间、错误码与 trace_id。输入锁定后新上传不影响当前任务；同期间同数据集计算中任务互斥。失败版本保持不可查询为正式结果，旧已发布版本始终可用。幂等键建议为 `period + dataset + sorted source version IDs + snapshot hash + rule versions + adjustment IDs`；用户要求强制重新生成时另传理由与新任务 ID，不允许静默覆盖。

## 6. 正式财务公式

下表为 V1.3 **已明确的规则**；未列出的利润中间项须落到财经批准的指标字典，不能以通用净利润公式推断三视角完整损益。

| 指标 | 公式/处理 |
|---|---|
| 金额 GAP | `ACT - BGT`；ACT-FC 为 `ACT - FC`，FC-BGT 为 `FC - BGT`，后两者仅在正式 FC 覆盖的模块启用 |
| 销售成本 | 已确认的材料＋人工＋外协＋制造变动＋制造固定；材料损耗若已含材料成本不重复加总；与源结果字段差异进勾稽 |
| 产品毛利润 | 收入－销售成本 |
| 损益毛利润 | 产品毛利润－闲置费用；产品毛利润保持不变 |
| 其他损益 | 资产减值损失＋信用减值损失；一期由财经结果导入，不重建上游计算 |
| 基地项目利润 | 损益毛利润－基地质量－基地 PMC－基地运营－基地其他－物流－销售－管理－研发－其他损益＋其他收益；实验室/制造体系若已在基地其他中，不再重复扣减 |
| 基地项目利润率 | 基地项目利润÷销售收入；分母 0 展示“—” |
| 当期/累计 | 当期取指定月；累计是当年 1 月至指定月各当期结果的合计。比率和单价用累计分子/分母重算 |
| 费用有利性 | 金额 GAP 仍为 ACT-BGT；收益类正 GAP 有利，成本/费用类正 GAP 不利；分母为 0 时百分比 GAP 显示“—” |

基地财务费用不取、销售费用只取宜昌 JV、管理及研发从三级费用归集；产品线不取销售/管理/财务费用；事业部取销售/管理三级费用且不取财务费用。基地信用减值当前无数据时展示 0 并保留“本期无数据”证据，不能当成制度性不取。对`无预算有实际`、`有预算无实际`、`电量为零`、`型号为空`设正常业务标签；总额保留，单位值不强算。未匹配必须归属项、配置冲突、比例不平、海外缺汇率、任一正式勾稽非零均阻断发布。

## 7. PVM 公式与分母边界

一期样表口径详见 [08-一期样表计算口径](08-一期样表计算口径.md)。每个样表型号有 `Pa/Pb` 实际/预算单价、`Qa/Qb` 实际/预算电量、`Ca/Cb` 单位成本、`Ma=Pa-Ca`、`Mb=Pb-Cb`、`Sb=Qb/ΣQb` 预算**电量**占比、`M̄b=Σ预算产品毛利/ΣQb` 预算平均单位毛利。收入桥接：价格`(Pa-Pb)×Qa`，销量`(ΣQa×Sb-Qb)×Pb`，结构`(Qa-ΣQa×Sb)×Pb`。毛利桥接：价格`(Pa-Pb)×Qa`，销量`(Qa-Qb)×M̄b`，成本`-(Ca-Cb)×Qa`，结构`(Qa-ΣQa×Sb)×(Mb-M̄b)`。样表原生桥接余数单列保留，不隐藏进因素。成本影响拆材料（不含损耗）、材料损耗、人工、外协、变动及固定制造，避免材料损耗重复计入。

一期 PVM 按样表型号汇总；客户项目多维 PVM 留待后续扩展。预算电量占比和平均单位毛利基于完整当前分析范围，不能因页面筛选重算。零量、新增、退出业务的收入差和产品毛利差全归结构因素，不除零。桥接余数保留并展示，不把残差藏进任一因素；样表原生 PVM 余数不阻断一期损益发布。PVM 只对产品毛利桥接，不能用扣闲置后的损益毛利冒充。

## 8. 非财务、FC 与新增指标

电芯优率：目标/实际同键配对，差额＝实际－目标，达成率＝实际÷目标（目标 0 为“—”）；仅一侧存在时另一侧显示缺失状态，不自动补 0。跨型号/基地不得直接平均百分比；一期巴长汇总只给达标与未达标型号数。标准范围及达标判断由财经/Owner 提供类目字典确认。FC 单独保存版本、基准月、覆盖期和正式采用状态，ACT/BGT/FC 三场景比较必须使用同一范围与明确结果版本；是否将 FC 接入各专题由能力矩阵决定，不默认全覆盖。

事业部基地×产品矩阵的“经营分析利润”独立于完整损益，已知剔除研发、运营及资产/信用减值，其余组成项**待确认**。YU 全称、公式、单位和来源**待确认**。线体单位制造费用暂按总制造费用元÷总电量 Wh 设计，但费用范围、线体、共线分摊和零量规则**待确认**。单位毛利瀑布暂以单位售价－单位成本及 BGT→ACT 桥接设计，单位、分母、因素和异常场景**待确认**。风险一页纸依确定性阈值或财经确认，阈值**待确认**，AI 只解释。这些项目不得将前端临时拼数作为正式结果。

## 9. 勾稽与数据质量报告

发布门禁至少报告：源行标准化控制总额（换算后）、分摊前后、费用池、成本组成与控制字段、各层级汇总、当期至累计、三视角同源对照、PVM 两座桥、调整前后、被排除/未映射金额和非财经独立性。所有正式金额/PVM 桥接差异容忍度为 **0**，使用未舍入值比较；界面因四舍五入的尾差只做显示说明。每项校验持久化 `check_code, expected, actual, difference, status, source_ids`，失败能定位源行、映射、分摊和规则版本。异常码遵循 V1.3 第 7.7 节的 IMP/MAP/ALL/FX/DQ/CFG/REC/SEC/SYS 分类。

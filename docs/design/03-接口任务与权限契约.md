# 接口、异步任务与权限契约

## 1. 契约边界

当前控制器统一在 `/api/v1` 下，`ApiResult<T>` 为 `{success,data,code,message}`；`success=true` 的业务结果仍可能处于等待数据或口径状态，调用方必须检查结果状态。下文标 **现有路由** 的仅表示源码有入口，不保证完整 V1.3 行为；标 **拟新增** 的路径/字段是实施建议，开发前须固化 OpenAPI、DTO、错误码和兼容策略。具体当前 DTO 以 [控制器源码](../../backend/analysis-api/src/main/java/com/sunwoda/evb/finance/analysis/api/controller) 为准，不能将本设计中的示例当成已部署 API。

统一请求约定（设计建议）：命令由认证主体确定 `operatorId`，客户端不得传工号冒充操作者；写命令带 `Idempotency-Key` 和预期资源版本 `If-Match`/`expectedVersion`，服务端审计保存请求追踪号；读请求携带明确的期间、视角、范围、结果版本和期间口径，默认版本由服务端按授权已发布版本选择。拒绝无权限参数，禁止“去掉无权范围后返回部分数据”却不告知调用者。分页统一 `page,size,sort`，设置上限并返回 `total`。时间统一 ISO 8601，金额以十进制字符串序列化，避免浏览器浮点损失；现有接口若为数值 JSON，迁移需另开兼容字段/版本并做契约测试。

建议响应的版本上下文：

```json
{
  "success": true,
  "code": "OK",
  "message": "成功",
  "data": {
    "period": "2026-08",
    "perspective": "BASE",
    "scopeId": "BASE-001",
    "periodMode": "CURRENT",
    "scenario": "ACT_BGT",
    "resultVersion": "R2",
    "publicationStatus": "PUBLISHED",
    "publishedAt": "2026-09-10T10:00:00+08:00",
    "rows": []
  },
  "traceId": "example-trace-id"
}
```

上述 `traceId` 顶层字段、数字字符串和版本字段为**目标契约**，非当前 `ApiResult` 已实现字段。对未完成数据或待确认口径，应返回明确状态/错误码，不返回伪造金额。

## 2. 路由清单：当前入口与目标能力

| 能力 | 源码中的现有路由 | 目标补齐与注意点 |
|---|---|---|
| 健康/目录 | `GET /health`、`GET /datasets`、`GET /metrics`、`POST /metrics` | 目录需含模板/字段版本；指标公式受控启用及审批试算尚需契约 |
| 批次/完整性 | `POST /batches`、`GET /batches/{batchNo}`、`POST /batches/{batchNo}/status`、`GET /batches/{batchNo}/readiness`、`GET /batches/{batchNo}/quality` | 批次号不是授权凭据；批次读取、readiness 和 quality 均校验用户在批次视角有可见范围。批次实体当前没有数据 scope 字段，因此这是视角级最低门禁，不等同于批次实际范围的细粒度授权；批次与范围绑定前不可宣称已完成行级隔离。批次创建及准备态 `CHECKING/READY_FOR_CALCULATION` 推进要求财经计算权限；通用 `/status` 拒绝计算、确认、发布等终态流转，只能由对应专用操作推动。 |
| 月度导入 | `POST /batches/{batchNo}/imports`、`GET /imports/{taskNo}`、`GET /imports/{taskNo}/issues`、`POST /imports/{taskNo}/validate`、`POST /imports/{taskNo}/status` | 拟新增模板下载、原始预览/错误文件下载、生效版本列表、整期覆盖确认；现有路由不能推定这些能力已完成 |
| 配置 | `GET/POST /mappings`、`POST /mappings/disable`、`POST /config/imports`、`GET /config/imports/{taskNo}`、`GET /config/imports/{taskNo}/issues`、上传/校验/状态子路由 | 拟新增库存档案、费用分类、汇率、分摊、基地粒度、指标公式试算与影响分析，均需对象级授权 |
| 计算/版本 | `POST /calculations`、`GET /calculations/{batchNo}`、`POST /calculations/confirm`、`POST /calculations/publish`、`GET /calculations/{batchNo}/versions`、`GET /calculations/{batchNo}/versions/{versionNo}/result`、`POST /calculations/revisions`、`GET /calculations/{batchNo}/trace` | db 普通计算已接入来源/事实快照与 R1/R2 历史结果读取；本轮当前状态和未完成范围见[计算版本与结果快照接口](../api/计算版本与结果快照接口.md)及[整改验证报告](../reports/2026-10-22-calculation-reliability.md)。拟增强任务阶段日志、版本比对、重算申请、撤回和报告下载 |
| 查询 | `GET /overview`、`GET /metric-tree/{batchNo}`、`GET /pvm/{batchNo}`、`GET /v13/overview/{batchNo}`、`GET /v13/matrix/{batchNo}`、`GET /v13/unit-efficiency/{batchNo}`、`GET /v13/forecast/{batchNo}`、`GET /v13/risk/{batchNo}`、`GET /v13/waterfall/{batchNo}`、`GET /v13/topics/{batchNo}/{topicCode}` | 某些 V1.3 路由返回待数据/待口径状态；不得以存在路由认定已交付。拟新增标准损益明细、非财经指标、累计/月份和已发布版本查询契约 |
| FC | `POST /fc-versions`、`POST /fc-versions/{versionCode}/snapshots`、`POST /fc-versions/{versionCode}/publish` | 逐模块确认 FC 能力；默认只用正式采用版，指定历史版本需授权且清楚标识 |
| AI/导出/审计 | `POST/GET /ai/analysis/{batchNo}`、`POST /ai/analysis/{batchNo}/publish`、`POST /exports`、`GET /exports/{taskId}`、`GET /exports/{taskId}/download`、`GET /audit-logs` | 本地 AI 适配器是规则摘要，导出下载已在生成与下载两个时点二次鉴权；拟新增草稿编辑/确认/撤回/分发、正式本地网关元数据、风险 PDF |

表中路径均省略统一前缀 `/api/v1`。例如源码 `/api/v1/v13/forecast/{batchNo}` 的 `scenario` 和 `fcVersion` 参数已存在，是否具备完整 ACT/BGT/FC 范围仍以服务实现、真实样本及 UAT 为准。前端目前已禁用未实现累计和通用页 FC；见 [展示整改报告](../reports/2026-10-21-financial-display-remediation.md)。

## 3. 关键目标接口草案（均拟新增或拟增强）

| 接口 | 请求字段 | 成功响应/失败条件 |
|---|---|---|
| `POST /batches/{id}/files` | `objectCode, templateVersion, file, expectedBatchVersion, replaceReason?` | 返回 `fileVersionId, taskId, RECEIVED`；无模板、越权、已发布且无重算申请时拒绝；文件解析异步 |
| `POST /batches/{id}/readiness-checks` | `datasetCode` | 返回必需/条件必需对象、生效文件版本、阻断/警告数；不隐式启动计算 |
| `POST /calculations/jobs` | `batchId, perspective, scopeIds, sourceVersionIds, expectedConfigHash?, idempotencyKey` | 返回任务 ID、冻结输入摘要与状态；同键复用/冲突有明确说明；单数据集并发互斥 |
| `GET /calculations/jobs/{id}` | 无 | 阶段、处理/异常行数、心跳、错误码、可重试性、结果版本；失败不返回部分正式金额 |
| `GET /results/{versionId}/pnl` | `periodMode, scenario, scopeIds, page` | 授权范围的指标行及公式/来源/trace；无发布权者不可查未发布版本 |
| `GET /results/{versionId}/pvm` | `perspective, filters` | 正式占比、筛选汇总、收入/毛利桥接差异分别标识；非零差异不得发布 |
| `POST /adjustments` | `period,perspective,scope,scenario,metricCode,amount,direction,reason,evidenceFileId,expectedVersion` | 返回调整 ID；源事实不改写；发布版本不随之变化 |
| `POST /results/{versionId}/confirm` / `/publish` | `expectedStatus, scopeIds, reason?, idempotencyKey` | 状态事务转换，阻断校验为 0；新发布版本替代旧发布指针；记录审计 |
| `GET /nonfinancial-results/{versionId}` | `period,baseIds,leaderIds,line,category` | 目标/实际、差额、达成率及缺侧状态；巴长型号权限按服务端映射快照判定 |
| `GET /risks/{versionId}/pdf` | 与页面相同筛选 | 按授权快照异步导出，PDF 与页面同版同规则，不能泄露底层明细 |

开放接口前需为每个目标接口形成 OpenAPI 示例、权限规则、状态码、分页/排序上限、幂等重放行为和失败示例。API 文档的字段名与数据库列名不用相同，但转换必须显式、可测试。现有专题说明见 [API 文档目录](../api)。

## 4. 任务与错误语义

异步任务统一状态建议为 `RECEIVED, VALIDATING, READY, RUNNING, SUCCEEDED, FAILED, CANCELLED`；计算细分标准化、映射、分摊、损益、PVM、勾稽和物化阶段。任务记录 `jobId, type, inputHash, actorId, startedAt, heartbeatAt, finishedAt, progress, processedRows, issueCount, errorCode, retryOf, traceId`。Worker 抢占需租约/令牌，过期后安全重试；外部通知使用 Outbox，投递幂等。源数据版本/配置快照在开始时冻结；重复任务不得新增两个有效版本。系统失败可重试，业务错误必须先修数据或配置后新建输入哈希。

错误响应建议包含稳定 `code`、可操作中文 `message`、`traceId` 和字段/源行定位，不在消息里泄露其他范围。HTTP 分类建议：400 格式，401 未认证，403 越权，404 不存在或不可见资源，409 并发/版本冲突，422 业务校验，429 限流，5xx 技术故障。保留需求错误码 `IMP-001/002/003, MAP-001/002, ALL-001, FX-001, DQ-001/002, CFG-001, REC-001, SEC-001, SYS-001`；业务码与 HTTP 码的映射在 API 评审中固化。不能把 PENDING_DATA_MODEL、PENDING_DEFINITION 等等待状态转换为 `0` 金额。

## 5. 权限模型与角色矩阵

授权判定为 `功能 × 视角 × 范围 × 数据层级 × 操作`，所有列表、详情、导出、PDF、追溯和 AI 上下文都在服务端过滤。工号是身份唯一键；`local` Profile 的 `X-User-Id` 仅本地开发使用。正式环境必须接入可信公司身份网关并校验签名/会话及权限有效性，不能信任普通请求头。用户失效立即拒绝新请求，历史审计保留。

| 角色 | 结果可见范围/状态 | 原始/标准明细 | 上传/配置 | 计算/确认/发布 | 导出/AI |
|---|---|---|---|---|---|
| 总部财经 | 三视角全域，草稿与已发布 | 有 | 全域 | 可发起、确认、按授权发布 | 明细导出；生成/审核/分发 AI |
| 总部运营 | 三视角全域**已发布** | 无 | 无 | 无 | 仅已授权汇总；只看已分发 AI |
| 基地财经 | 授权基地，草稿与已发布 | 本基地 | 本基地授权对象 | 按单独授予的操作权 | 本基地明细；本基地 AI 草稿 |
| 产品线/事业部 BP | 授权产品线/事业部，草稿与已发布 | 本范围 | 本范围授权对象 | 按单独授予的操作权 | 本范围明细；本范围 AI 草稿 |
| 基地巴长 | 本基地已发布看板与损益 | 无 | 无 | 无 | 不导出；仅分发的 AI |
| 基地运营 | 本基地已发布损益 | 无 | 无 | 无 | 不导出；仅分发的 AI |
| 产品线/事业部巴长及运营 | 本范围已发布看板与损益 | 无 | 无 | 无 | 仅授权汇总导出；分发的 AI |
| 非财经巴长 | 本人工号映射的型号结果 | 无 | 无 | 无 | 依单独导出权，仅本人范围 |
| 财经 IT 管理员 | 技术任务/模板/权限视图按授权 | 业务明细非默认 | 技术配置 | 可重试技术任务，不代财经确认 | 审计与技术日志 |
| 审计只读 | 授权范围已发布版与操作日志 | 按独立授权 | 无 | 无 | 按审计授权 |

总部财经的发布权、上传权分别授予，不因角色名称自动合并。阿米巴项目组可全域看结果与底稿，但发布仍需独立授权。预算占比表仅使用“名称包含授权基地名称”的特殊分发规则，不扩展到正式归属。非财经巴长只按映射快照中的型号→本人巴长工号，不以基地替代。无明细但可导出的角色只能得到页面已有权查看的汇总。审计日志记录工号、时间、对象、前后值摘要、IP/终端、结果与追踪号；敏感财务行不进入普通应用日志。

## 6. 权限测试契约

对每个查询/下载端点至少测试：无认证、无功能权、跨视角、跨范围、仅汇总权访问明细、篡改 URL/筛选、已撤回或未发布版本、用户失效、授权变更后旧下载链接、巴长同型号跨基地。导出任务在生成和下载两个时点校验；AI 上下文在模型调用前校验，草稿/分发再次校验。SQL 层必须带授权 scope 限制或在仓储边界验证完整集合，不允许仅前端隐藏菜单。

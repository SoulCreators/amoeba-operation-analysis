# 第二阶段：财经展示与查询边界整改报告

日期：2026-10-21
分支：`codex/refactor/enterprise-project-structure`
前置报告：[第一阶段代码评审与目录优化](2026-10-21-enterprise-review.md)

## 1. 本轮结果

针对 FIN-02、FIN-03，已移除前端合成 FC 的路径，阻止缺失/未发布/不匹配的数据被渲染为有效对比，禁用未实现的累计和自定义月份筛选。修复了浏览器回归发现的重复创建批次竞态。

前端 62 项单测、4 项浏览器测试和生产构建通过；新增 23 项有数据的组件回归用例。没有改动后端计算、认证、数据库 SQL 或依赖版本。本轮是展示边界整改，不代表完整累计计算、生产认证或不可变计算版本已经实现。

## 2. 行为变化

| 场景 | 原行为/风险 | 当前行为 |
|---|---|---|
| 总览、矩阵切换 FC | 客户端存在 `BGT + (ACT-BGT) × 0.72` 默认预测，矩阵把 ACT 填入 FC 槽位 | 删除插值及 FC 槽位；总览和矩阵固定 ACT/BGT，FC 选择仅在预测页开放 |
| 初次进入预测页 | 将“待导入正式预测版本”提示文字作为版本参数 | 进入 ACT_FC；版本留空时省略参数，由服务端选择正式版本 |
| 指定预测版本 | 无有效版本身份核验 | 规范化输入空白；响应版本必须等于显式指定版本 |
| 缺版本、快照部分覆盖、草稿 | 页面可能直接展示响应 rows | 只接受 CALCULATED、PUBLISHED、非空版本且金额完整的响应；否则清空表格并展示阻断原因 |
| 响应返回其他批次/视角/场景 | 仅做部分请求序号保护 | 总览、矩阵、预测同时检查批次、视角、场景；预测还检查发布状态及版本 |
| 延迟旧响应 | 场景和刷新请求可能交错 | 清空旧分析并递增请求序号；旧响应不能写入新场景；显式刷新先完成批次读取，再查询分析 |
| 旧总览 API 返回 | 与 V1.3 结果共用显示数组 | 分离工作台展示数组，旧 API 响应不能覆盖当前批次的指标 |
| 矩阵指标 | 前端 GROSS/PROFIT 与后端标准编码不一致 | 发送 GROSS_PROFIT / NET_PROFIT，并检查返回的 metricCode |
| 矩阵缺产品维度 | 可能把聚合行展示成产品矩阵 | PENDING_DATA_MODEL 或缺维度/金额时不渲染矩阵数字 |
| 利润名称 | NET_PROFIT 显示为营业利润/经营分析利润 | 指标卡改为净利润；矩阵标注净利润及产品归属费用范围，不改变计算公式 |
| 累计/自定义月份 | 有选择项但无对应后端聚合契约 | 当期为默认；累计与自定义月份禁用并说明尚未支持；毛利页移除无效切换 |
| 分析期间 | 默认固定月份可能与实际批次不符 | 分析页显示读取到的批次期间；导入页保留新批次期间选项 |
| 首次加载立即进入导入页 | 两次 ensureBatch 同时创建相同批次，导致“批次号已存在”和空数据集 | 同一批次的在途加载/创建共用 Promise；完成或失败后释放，后续仍可重试 |

显式 FC 版本可以是已发布的历史版本；留空时由既有服务端选择 official 版本。前端校验不替代服务端鉴权，也未改变服务端允许查询草稿的接口行为。

## 5. 问题关闭范围与剩余工作

- **FIN-02：本轮关闭已发现的前端替代 FC、场景误标和不完整快照展示路径。** 总览/矩阵 FC 能力仍未开发；通过禁用不支持的选择保持状态真实，后续扩展必须建立后端契约和样本。
- **FIN-03：本轮关闭未实现累计/自定义功能却提供正式选择的展示风险。** 累计分析本身没有实现；跨月集合、缺月、版本选取、比率重算与财经验收仍是后续工作。
- **FIN-01、SEC-01 等保持待办。** 普通计算版本与输入快照贯通、生产认证、财务口径冻结、迁移历史及恢复演练不在本轮完成范围内。
- 当前前端仍以工作台组件集中编排；本轮新增独立展示校验模块，尚未完成全部页面和状态的领域拆分。

后续优先处理计算版本链路与生产认证，累计功能需先形成批准的业务规则。本轮文件仍仅保留在本地分支，未提交、推送或部署。

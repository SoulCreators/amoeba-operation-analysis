# 1. 项目背景、目标与范围

## 1.1 建设背景

当前阿米巴经营分析以Excel为主要载体。不同视角分别依赖收入成本、期间费用、闲置费用、研发费用、减值损失等多张底稿，经人工映射、公式加工和反复校验后形成损益表、经营看板、PVM及分析报告。现状具有以下风险：

1. **规则分散**：核心口径固化在个人Excel公式及经验中，难以继承、复用和解释。
2. **数据链条脆弱**：源工作簿存在大量外部链接、`#REF!`、`#DIV/0!`及`#N/A`，格式或引用变化容易导致结果失真。
3. **处理耗时**：每月需要重复清洗、匹配、汇总、拆分和分发，财经大量时间消耗在数据加工。
4. **权限粗放**：依靠拆分文件分发，难以持续保证基地、产品线、事业部之间的数据隔离。
5. **分析滞后**：经营结果生成后仍需人工识别差异、整理亮点和风险，无法快速服务经营会议。

本项目不照搬现有Excel，而是将其中已经确认的财务口径转化为平台规则，并保留Excel中有价值的公式链路作为口径证据。源表中错误公式、失效外链和临时辅助列不得直接进入正式计算逻辑。

## 1.2 一期建设目标

| 目标 | 一期结果 |
|---|---|
| 统一数据入口 | 支持各类实际、预算、结果及配置数据按月度批次上传、校验和替换 |
| 固化确定性计算 | 由规则引擎统一完成映射、分摊、损益、GAP、PVM及指标计算 |
| 支持三类视角 | 同一平台输出基地、产品线、事业部分析，并明确共同能力与差异口径 |
| 实现权限隔离 | 用户只查看授权范围；经营人员不得查看未授权底层明细 |
| 建立闭环 | 数据异常可定位、可忽略、可修正、可重算，结果可确认、发布、追溯 |
| 形成智能分析 | 财经主动触发本地AI，生成固定结构的经营分析草稿并受控分发 |

## 1.3 一期范围

### 1.3.1 纳入范围

- 2026年1月起的历史数据及后续月度数据。
- 国内生产基地，以及海外匈牙利、泰国基地。
- 基地汇总、单基地、产品线、事业部经营分析。
- 实际、年度预算、GAP、当期、累计口径。
- 损益表、经营看板、指标树、PVM、项目/产品毛利、AI分析。
- 非财经指标分析（一期以“电芯优率”为示例）：目标值/实际值对比、差额、达成率及巴长权限隔离。
- 映射、分类、分摊比例、汇率、用户权限等配置。
- 批次、异常、重算、确认、发布、导出和审计。

### 1.3.2 一期不纳入范围

- 不直连ERP、PMS、预算、共享、BI等系统，所有业务数据由人工导入。
- 不由AI计算正式财务结果、自动修改底层数据或自动发布分析。
- 不建设预算编制、预测编制及源业务单据处理功能。
- 不系统化重建信用减值、资产减值的上游复杂计算；一期直接导入财经确认后的结果。
- 损耗、物流费等仍需大量手工识别的特殊规则，仅按已确认的数据或模板承接；未确认部分列入二期。
- 不因一期上线而取消财经复核责任。

## 1.4 成功标准

1. 同一批次内，损益、PVM及明细勾稽无未解释差异；正式财务勾稽差异容忍度为0。
2. 未匹配、重复匹配、比例不平、模板错误等问题可被系统明确识别，不静默丢数。
3. 任何发布结果均可追溯至批次、模板、源文件、配置快照、计算任务及操作人。
4. 基地、产品线、事业部人员只能查看其授权范围；明细权限与看板权限独立控制。
5. 财经可在不改代码的情况下维护常用映射、费用分类和分摊比例。
6. AI输出使用已确认的计算结果和授权明细，并经财经确认后分发。

# 2. 总体方案与关键设计决策

## 2.1 总体处理链路

> 模板下载 → 分项上传 → 文件及字段校验 → 月度批次完整性检查 → 映射与分摊 → 异常处理 → 财经点击“开始计算” → 三视角结果生成 → 勾稽校验 → 财经确认 → 发布/分发 → 看板与AI分析

平台采用“统一数据与能力底座＋三套分析规则”的结构：导入、批次、配置、权限、审计、发布和AI等能力统一建设；基地、产品线、事业部按各自业务粒度、费用口径和PVM规则独立计算，禁止用一个视角的规则套算另一个视角。

## 2.2 关键设计决策

| 编号 | 决策 | 设计含义 |
|---|---|---|
| DD-001 | 一期人工导入 | 不依赖外围系统接口，优先保证月底可用；接口预留二期扩展点 |
| DD-002 | 两套收入成本数据对象 | 基地使用独立收入成本表；产品线与事业部共用另一套收入成本表 |
| DD-003 | 预算与实际分离 | 预算全年固化后低频更新，实际按月更新；GAP由系统计算，不导入GAP表 |
| DD-004 | 核心明细整期覆盖 | 同期间再次上传核心明细时生成新版本并整体替换该期间旧版本，不做行级混合 |
| DD-005 | 映射配置增量维护 | 映射可新增、更新、失效，不设置生效期间和多版本；调整后可按授权重算历史 |
| DD-006 | 规则计算与AI分离 | 公式、映射、分摊由确定性引擎执行；AI只做解释、归因线索和建议 |
| DD-007 | 结果不可直接改 | 正式结果由源数据、配置及受控调整共同计算；不允许在看板或损益表直接改数字 |
| DD-008 | 财经主动计算与发布 | 上传完成后不自动生成结果；由财经点击计算、确认并决定发布时间和对象 |
| DD-009 | 零容差勾稽 | 财务金额及PVM桥接必须精确勾稽；显示四舍五入差异不进入底层校验 |
| DD-010 | 配置快照随结果保存 | 每次计算固化配置快照，防止后续配置变化导致已发布结果无法解释 |
| DD-011 | 基地分析粒度可配置 | 普通业务由各基地选择“基地＋型号＋项目”或“基地＋型号”，同一结果版本统一执行所选粒度 |
| DD-012 | 基地特殊业务优先识别 | 基地零售、B品按客户项目改分别归类并忽略型号汇总；产品线和事业部仍将零售、B品统一归为B品 |

## 2.3 共用能力与视角差异

| 能力 | 基地 | 产品线 | 事业部 |
|---|---|---|---|
| 批次、导入、校验、异常、审计 | 共用 | 共用 | 共用 |
| 收入成本源表 | 基地专用 | 产品线/事业部共用 | 产品线/事业部共用 |
| 归属主维度 | 收入计算基地 | 产品线 | 事业部 |
| 核心分析粒度 | 普通业务按基地配置为“基地＋电芯型号＋客户项目改”或“基地＋电芯型号” | 默认产品线＋电芯型号，部分产品线按项目 | 事业部＋客户项目＋电芯型号 |
| 特殊业务 | 按客户项目改识别；零售、B品分别汇总，不考虑电芯型号 | 客户简称改2为零售/B品时统一归B品并单列收入 | 客户简称改2为零售/B品时统一归B品并单列收入 |
| 闲置费用 | 结果导入；从损益毛利润扣减 | 结果导入；从损益毛利润扣减 | 结果导入；从损益毛利润扣减 |
| 财务费用 | 不取 | 不取 | 不取 |
| 销售费用 | 仅宜昌JV | 不取 | 取三级费用明细 |
| 管理费用 | 取三级费用明细，按费用匹配表归集 | 不取 | 取三级费用明细 |
| 研发费用 | 取三级费用明细，按费用匹配表归集 | 按项目映射及比例/指定分配 | 按项目映射及比例/指定分配 |
| 减值 | 结果导入；当前基地无信用减值数据，未提供时为0 | 信用、资产减值结果导入 | 信用、资产减值结果导入 |
| PVM | 基地逻辑 | 产品线独立逻辑 | 事业部独立逻辑，项目小计不重算正式占比 |

# 3. 用户、角色与职责

## 3.1 业务职责

| 角色 | 主要职责 |
|---|---|
| 总部财经 | 维护全局配置，上传数据，处理异常，发起计算，复核三视角结果，确认和发布AI分析 |
| 总部运营 | 查看全域已发布经营结果、PVM、指标树、非财经指标及已发布AI分析，不维护底层数据、配置或发布结果 |
| 基地财经 | 在授权基地内查看/维护数据，协助核对基地结果和AI草稿 |
| 产品线财务BP | 在授权产品线内维护配置、核对结果、查看明细并参与发布前确认 |
| 事业部财务BP | 在授权事业部内维护配置、核对结果、查看明细并参与发布前确认 |
| 非财经指标业务Owner（经营管理中心） | 提供电芯优率口径、目标/实际数据和类目说明，确认指标结果；不维护独立巴长映射表 |
| 阿米巴项目组 | 查看全量结果与底稿，负责集中核验和发布协调 |
| 巴长/运营 | 按授权范围查看正式发布结果，不参与底层数据维护和财务计算 |
| 财经IT管理员 | 维护模板、参数、角色、任务及接口配置，排查技术异常，不代替财经确认业务口径 |
| 审计/只读人员 | 在授权范围内查询已发布版本及操作日志，不修改数据 |

## 3.2 用户权限初始化模板

系统应支持Excel导入用户权限，至少包含：姓名、工号、用户角色、数据视角、可查看范围、明细查看权限、数据导出权限、配置维护范围、是否有效、备注。工号作为用户唯一识别字段，姓名仅展示。

## 3.3 职责分离

- 上传者可以发起计算，但发布权限应单独授予。
- 财经IT可重试技术任务，不得修改财经业务结果。
- 巴长、基地运营、产品线运营及事业部运营不得查看未发布结果或底层明细。
- AI分析的生成、编辑、确认、分发应保留独立操作记录。

# 4. 业务流程与状态管理

## 4.1 月度业务流程

1. 总部财经创建分析期间或沿用系统自动生成的月度期间。
2. 按“基地数据集”和“产品线/事业部数据集”分别下载模板、上传文件。
3. 系统完成文件级、字段级、行级、映射级及跨表校验。
4. 财经在异常工作台处理阻断项；警告项可以修正或受控忽略。
5. 全部必需数据达到可计算状态后，财经点击“开始计算”。
6. 系统按配置快照依次执行标准化、映射、分摊、损益、PVM、指标及勾稽。
7. 财经查看计算报告，确认或退回修正；修正后创建新计算版本。
8. 财经确认结果并发布，系统按权限开放看板和报表。
9. 财经按需点击生成AI分析，编辑、确认后向授权对象分发。

## 4.2 月度批次状态

| 状态 | 进入条件 | 允许操作 | 退出条件 |
|---|---|---|---|
| 草稿 | 创建期间 | 上传、删除未生效文件、维护说明 | 至少上传一个文件 |
| 数据准备中 | 存在上传记录 | 继续上传、重传、查看校验 | 必需项齐全且无阻断错误 |
| 校验不通过 | 存在阻断错误 | 下载错误、修复、重传 | 阻断错误清零 |
| 待计算 | 完整性通过 | 开始计算、补充数据 | 财经发起计算 |
| 计算中 | 已创建计算任务 | 查看进度，不允许修改本批次源数据 | 成功或失败 |
| 计算失败 | 技术或业务校验失败 | 查看日志、处理后重算 | 新计算任务成功 |
| 待确认 | 计算成功且勾稽通过 | 查看、导出、退回、确认 | 财经确认或退回 |
| 已确认 | 结果已确认 | 发布、生成AI、查看 | 发布或新版本替代 |
| 已发布 | 已执行发布 | 按权限查询、导出、AI分发 | 重算后发布新版本 |
| 已替代 | 同期间新版本发布 | 只读追溯 | 终态 |

## 4.3 AI分析状态

未生成 → 生成中 → 草稿 → 已确认 → 已分发 → 已替代。生成失败可重试；新计算结果发布后，旧AI分析自动标识“对应旧结果版本”，不得自动沿用。

## 4.4 并发及锁定

- 同一期间、同一数据集只允许一个“计算中”任务。
- 计算开始时锁定源数据版本和配置快照；计算中新增上传不影响当前任务。
- 已发布结果不得覆盖，重算必须产生新结果版本。
- 同一映射项多人编辑时采用乐观锁，后保存者收到冲突提示并重新加载。

## 6.3 统一维度

平台至少管理以下维度：期间、公司、基地、出货基地、收入计算基地、事业部、产品线、客户简称、客户项目改、电芯型号、物料、产品类别、特殊业务类型、基地分析粒度模式、费用分类、研发项目、会计科目、组织、币种、场景（实际/预算）、口径（当期/累计）。

“二级巴长”仅作为Excel辅助分配字段保留，不作为正式维度、映射键、计算粒度或权限条件。

## 6.4 数据精度与单位

- 原币金额、折算金额、数量、单价、比例分别保存，不用格式化展示值参与计算。
- 建议金额使用高精度小数，比例至少保留8位小数；展示层再按万元、元/kWh、GWh或百分比格式化。
- 实际金额统一标准化为人民币元；电量统一为kWh。预算模板若为万元/GWh，应在标准层明确换算。
- 国内基地汇率为1；匈牙利、泰国按财经上传的期间/基地汇率折算，并保存原币、汇率和人民币金额。
- 除数值展示外，所有勾稽使用未舍入的底层数值。

## 7.3 模板控制

### FR-IMP-001 模板版本

每类数据对象均分配模板编码与版本。模板包含字段编码、字段名称、类型、是否必填、取值规则、单位及示例。上传时系统读取隐藏的模板标识或模板元数据，不按Excel列位置猜测字段。

### FR-IMP-002 格式变化处理

1. 必填字段缺失、名称无法识别、数据类型错误时，文件整体不进入有效批次。
2. 新增未知列可作为原始字段保留，但不参与计算，并提示“未纳入字段”。
3. 字段顺序变化不影响计算，前提是字段编码/名称仍可匹配。
4. 字段改名只能由管理员在模板版本中显式配置别名，禁止系统自动模糊匹配。
5. 模板升级后旧模板是否可继续使用由模板状态控制；失效模板上传时阻断并提示下载新模板。

## 7.4 上传校验

| 层级 | 校验内容 | 处理 |
|---|---|---|
| 文件级 | 文件类型、大小、损坏、密码、模板版本、重复文件 | 阻断 |
| Sheet级 | 必需Sheet、重复Sheet、隐藏关键Sheet | 阻断或警告 |
| 字段级 | 必填字段、类型、长度、枚举、日期、金额、比例 | 阻断 |
| 行级 | 业务键为空、重复行、非法值、除零风险 | 阻断/警告 |
| 映射级 | 未匹配、多匹配、已失效分类、比例不平 | 按规则阻断或警告 |
| 跨表级 | 期间一致、实际/预算对象一致、控制总额、必需数据齐全 | 阻断 |
| 权限级 | 上传人是否有该视角/范围维护权 | 阻断 |

## 7.5 完整性检查

系统按“期间＋数据集”展示数据清单：必需、条件必需、可选。只有必需项生效版本齐全、阻断错误为0时，批次才进入“待计算”。基地三级费用明细为必需数据对象；减值结果按期间检查，当前确无信用减值时由财经勾选“本期无数据”并留痕，不以“不取”替代无数据状态。其他业务项明确无数据时同样填写原因，不以空文件代替。

## 7.6 重传与覆盖

- 核心数据按期间整期覆盖。重传先校验，成功后再切换生效版本，避免失败文件破坏现有批次。
- 系统保留旧文件、旧标准数据及文件哈希；页面默认显示当前生效版本。
- 同一文件重复上传时提示重复；用户确认后仍可形成新版本，但需说明原因。
- 已发布期间重传数据必须创建“重算申请”，不能直接改变已发布结果。

## 7.7 异常等级与错误码

# 8. 映射、分类及分摊配置

## 8.1 销售项目映射

### 8.1.1 业务键与输出

以“出货基地＋客户简称＋客户项目改＋电芯型号”为精确匹配键，输出事业部、产品线及必要辅助属性。实际和预算共用同一套映射关系。客户统一使用客户简称，项目统一使用财经修正项目。

### 8.1.2 匹配规则

1. 所有键值先执行去首尾空格、全半角统一等标准化，但不做可能改变业务含义的模糊匹配。
2. 精确命中一条有效记录则成功。
3. 未命中进入未匹配清单；命中多条不同归属进入冲突清单并阻断。
4. 电芯型号为空时不得虚构型号，可归入“型号为空”正常展示行，但产品线/事业部映射是否成功仍按完整业务键判断。
5. 产品线、事业部视角中，`客户简称-改2`为“零售”或“B品”的实际数据统一归为“B品”，不再细分零售。
6. 基地视角不使用`客户简称-改2`识别特殊业务；系统根据`客户项目改`分别识别“零售”和“B品”，两类不得合并。

### 8.1.3 非财经巴长复用规则

非财经指标不单独建设巴长映射表，直接复用本表销售项目映射中的可选字段“巴长”“巴长工号”。非财经巴长匹配**仅使用电芯型号**，不把基地、拉线、客户或项目加入匹配键：

1. 一个电芯型号只能命中一个有效巴长；同一巴长可以维护多个电芯型号。
2. 同一电芯型号在不同基地出现时，仍按同一巴长归属，基地仅用于页面筛选和授权范围判断。
3. 电芯型号未匹配、命中多个有效巴长或命中已失效记录时，进入非财经指标未匹配提醒；有权限的财经人员可补充/失效映射后重算。
4. 映射更新采用增量维护，不设置生效期间和版本号；计算结果保存映射快照，历史结果不被静默改变。
5. 非财经巴长只能看到映射到本人巴长工号的电芯型号数据，不因切换基地而扩大可见范围。

## 8.2 库存档案映射

物料编码映射产品类别、电芯型号、事业部和产品线。同一物料确需分属多个归属时，财经维护分摊比例；有效比例合计必须为100%。系统按比例同时分摊数量和金额，并保留原始总额、分配后金额和分摊规则ID。

## 8.3 费用分类字典

费用分类通过导入和页面维护两种方式管理，支持每月新增。基地费用匹配业务键为“公司＋事业部＋三级部门＋OU基地”，输出费用分类、收入计算基地及必要的分析归属。基地质量、PMC、运营、其他、销售、管理和研发费用均通过该匹配表确定归属；同一明细不得同时命中多个有效分类。分类为空、无效或已停用的行保留在异常清单，但不纳入正式计算；不得静默计入“其他”。

## 8.4 汇率配置

汇率由财经随基地维度数据导入或在配置中心维护。唯一键为期间＋收入计算基地＋原币。国内基地为1；海外基地必须提供汇率。缺失汇率时相关行阻断计算。系统保存换算方向和原始汇率值，不自行访问外部汇率源。

## 8.5 分摊比例

### 8.5.1 基地实验室及制造体系费用

按“期间＋费用池＋收入计算基地”维护比例。系统先将期间费用归集到费用池，再按基地比例分摊并汇入基地其他费用。比例可变、无审批，但必须合计100%，且保存维护人和时间。

### 8.5.2 总部费用至产品线/事业部

总部费用先按财经确定比例分至基地，再由基地拆分至线体，最终映射至产品线/事业部。系统应保存每一步分摊链路，支持从结果下钻查看“原费用→基地→线体→分析对象”。

### 8.5.3 产品线和事业部研发费用

产品线和事业部有明确项目的研发费用按项目映射；公共或无法直接映射的费用由财经维护比例或指定接收对象。指定分配优先于比例分配。每个分配批次必须总额守恒。基地研发费用不执行该分摊链，直接从三级费用明细按费用匹配表归集。

## 8.6 基地分析粒度配置

基地普通业务支持两种正式分析粒度：

1. `BASE_MODEL_PROJECT`：收入计算基地＋电芯型号＋客户项目改。适用于同一型号下存在多个需要分别分析的项目；系统先将同一项目的多条明细合并，再按电芯型号形成小计。
2. `BASE_MODEL`：收入计算基地＋电芯型号。适用于只需按型号分析的基地；该型号下全部客户项目合并为一条正式结果，项目仅在授权明细中保留。

每个基地只能存在一条有效配置，默认采用`BASE_MODEL_PROJECT`，由总部财经或授权基地财经维护，无需审批。配置不设置生效期间和独立版本号；调整会提示受影响月份，只有主动重算才影响历史结果，每次计算均保存配置快照。

特殊业务优先于普通粒度配置。`客户项目改`为“零售”或“B品”时，系统分别按“收入计算基地＋特殊业务类型”汇总，不考虑电芯型号，也不再按客户项目拆分。原始型号和项目仍保存在明细层供追溯。

## 8.7 配置维护控制

- 配置支持新增、更新、失效、批量导入和导出，不设置生效期间或独立版本号。
- 已失效记录保留，不物理删除。
- 映射调整影响历史月份。保存时系统提示受影响期间和已发布版本；重算需显式确认。
- 计算时生成不可变配置快照。即使当前配置改变，历史结果仍可按快照解释。
- 未匹配警告可由有权限的财经选择忽略。忽略后数据归入“未映射”，保留金额、操作人、时间和理由；若该数据属于计算必需归属，则仍阻断发布。

## 8.8 指标字典与确定性规则配置

指标和报表项会随经营管理要求调整，平台必须支持受控配置，不能将全部名称、顺序和展示逻辑写死。指标字典至少包含：指标编码、指标名称、适用视角、上级指标、来源类型、来源字段/组成指标、计算方式、实际/预算适用性、金额/比率/单价单位、收益类/成本类属性、显示顺序、是否允许下钻、是否有效、口径说明。

确定性规则分为三类：

1. **展示配置**：名称、顺序、单位、层级、是否显示，可由管理员配置后直接生效。
2. **受控公式**：只允许使用平台白名单运算符、已登记指标和聚合函数；保存时校验循环依赖、除零和单位一致性，经试算通过后启用。
3. **复杂规则**：PVM、多步分摊、特殊业务判断等由后端版本化实现，只在配置中选择规则版本，不允许用户录入任意SQL或脚本。

公式变更必须产生规则版本并记录变更前后、影响视角、测试结果和启用时间。已发布历史结果继续引用原规则快照；如需应用新规则，必须重算。

## 8.9 配置页面交互

- 列表支持按配置类型、有效状态、归属范围、更新时间筛选。
- 编辑时显示“当前被哪些期间/数据对象使用”；影响已发布期间时二次确认。
- 批量导入采用“预检查→差异预览→确认写入”，展示新增、更新、冲突和无变化数量。
- 失效前检查是否会造成当前待计算批次未匹配；有影响时明确提示。
- 分摊配置提供比例合计、未分配金额和分配链路预览。
- 指标公式提供至少三组样例试算结果及与现行版本差异。

# 9. 统一计算引擎

## 9.1 计算顺序

1. 锁定源文件版本与配置快照。
2. 字段标准化、单位换算、币种折算。
3. 去重及业务键检查。
4. 执行销售项目、库存、费用及研发映射。
5. 识别基地零售、B品特殊业务，并为普通业务加载各基地分析粒度配置。
6. 执行基地、总部、研发等分摊。
7. 应用有效人工调整。
8. 按视角和有效粒度计算损益项目。
9. 计算实际、预算、GAP、当期及累计指标。
10. 计算PVM及专项分析。
11. 执行总额守恒、跨表勾稽、权限范围完整性校验。
12. 写入结果版本、计算日志和校验报告。

## 9.2 场景与期间口径

- 实际：所选月份实际数据。
- 预算：默认采用年度预算中对应月份；如仅有年度预算分解表，按模板字段直接读取，不由系统主观拆分。
- 当期：指定月份。
- 累计：当年1月至指定月份。
- GAP：金额类默认“实际－预算”。收入、利润等收益类正数为有利；成本、费用类正数为不利，系统依据指标属性显示有利/不利。

## 9.3 通用公式

| 指标 | 公式/规则 |
|---|---|
| 销售成本 | 按视角启用的正式组成项加总：材料成本＋人工成本＋外协费用＋制造变动费用＋制造固定费用；材料损耗若已包含在材料成本中不得重复加总 |
| 产品毛利润 | 销售收入－销售成本 |
| 损益表毛利润 | 产品毛利润－闲置费用 |
| 其他损益 | 资产减值损失＋信用减值损失 |
| 考核利润 | 按各视角损益结构计算；基地公式见10.3，产品线和事业部按各自指标字典执行 |
| 毛利率/利润率 | 分子÷销售收入；收入为0时按零值展示规则处理 |

收入成本表中的销售成本结果字段作为控制参考；若表内存在已确认的组成公式，正式销售成本优先由组成项加总计算。两者差异必须进入勾稽报告，不允许反向覆盖组成项。

## 9.4 零值及缺失展示

| 场景 | 展示及计算 |
|---|---|
| 无预算有实际 | 预算0、实际正常、GAP=实际；标记“新增/预算缺失”，不视为系统错误 |
| 有预算无实际 | 实际0、预算正常、GAP=-预算；标记“未发生” |
| 电量为0 | 总额保留；单价、单位成本、率类显示“—”，不得产生无穷或错误值 |
| 型号为空或0 | 归入“型号为空”，保留金额并提示数据质量，不作为技术异常 |
| 不计算 | 从基地损益、PVM、指标树及总计中排除，保留在数据质量查询 |
| 分类无效/停用 | 不纳入计算，进入异常明细 |

## 9.5 勾稽控制

- 源明细总额＝标准化明细总额（考虑汇率换算后的控制口径）。
- 分摊前总额＝分摊后总额。
- 组成项合计＝损益对应项目。
- 各分析对象合计＝视角汇总。
- 当期累计＝当年1月至指定月各当期结果之和。
- PVM各因素合计＝实际与预算差异。
- 财经金额差异容忍度为0；若仅因页面展示四舍五入产生差异，底层校验仍应为0并在页面说明。

## 9.6 计算结果标准结构

每条指标结果至少包含：结果版本、期间、视角、分析对象类型与ID、上级对象、基地分析粒度模式、特殊业务类型、当期/累计、实际值、预算值、GAP、有利/不利、单位、币种、指标编码、配置快照、源记录数、调整金额、计算时间。前端不得自行重新计算正式指标，只负责格式化展示。

每条结果应能返回`trace_id`，用于查询：源数据行、映射记录、分摊链路、人工调整、公式版本和计算日志。对于仅有汇总权限的用户，追溯接口只返回口径说明，不返回未授权明细。

# 10. 基地视角详细设计

## 10.1 基地定义

出货基地取自原始导入数据；收入计算基地由财经在导入前整理，是基地分析的正式维度。一条基地收入成本明细只能对应一个收入计算基地。“不计算”是合法取值，该数据不纳入基地全部统计及PVM。

## 10.2 基地分析粒度

基地普通业务不采用全局固定粒度，而是按基地读取分析粒度配置：

- 选择“型号＋项目”时，正式粒度为“收入计算基地＋电芯型号＋客户项目改”。同一型号下相同客户项目改的多条明细先合并为一个项目结果，页面再向上汇总为型号小计和基地合计。
- 选择“型号”时，正式粒度为“收入计算基地＋电芯型号”。同一型号下不同客户项目改合并汇总，项目只作为明细追溯字段。

基地特殊业务使用独立粒度：当客户项目改为“零售”或“B品”时，分别按“收入计算基地＋零售”“收入计算基地＋B品”汇总，不考虑电芯型号。系统必须保留原型号及项目，确保结果可以下钻追溯。

## 10.3 基地损益口径

| 项目 | 实际来源/公式 | 预算来源/公式 | 特殊规则 |
|---|---|---|---|
| 电量、收入 | 基地实际收入成本明细 | 基地预算收入成本明细 | 海外按汇率折算 |
| 销售成本 | 材料＋人工＋外协＋制造变动＋制造固定 | 同公式 | 结果字段用于勾稽；材料损耗不重复加总 |
| 产品毛利润 | 收入－销售成本 | 同公式 | 不含闲置费用 |
| 损益毛利润 | 产品毛利润－闲置费用 | 同公式 | 巴长考核口径使用此结果 |
| 零售收入、B品收入 | 基地收入成本明细按客户项目改分别汇总 | 基地预算收入成本明细按同一规则汇总 | 两类分别列示，均不考虑电芯型号 |
| 基地质量/PMC/运营/其他 | 三级费用明细按分类及基地归集 | 预算三级费用明细 | 分类无效不取 |
| 实验室及制造体系 | 费用池按基地比例分摊 | 预算比例/结果 | 比例财经维护，无审批 |
| 物流费 | 基地物流费源表或已确认公式 | 预算物流费 | 纳入基地项目利润 |
| 销售费用 | 仅宜昌JV相关分类 | 对应预算 | 其他基地不取 |
| 管理费用 | 三级费用明细按费用匹配表归集 | 对应预算三级费用 | 命中有效管理费用分类后纳入 |
| 研发费用 | 三级费用明细按费用匹配表归集 | 对应预算三级费用 | 命中有效研发费用分类后纳入 |
| 财务费用 | 不取 | 不取 | 报表保留行并显示0/— |
| 资产减值 | 财经确认的减值结果导入 | 对应预算结果 | 平台不重建上游计算 |
| 信用减值 | 财经确认的减值结果导入 | 对应预算结果 | 当前基地无信用减值数据时为0，并记录本期无数据 |
| 其他收益 | 有结果数据时导入 | 对应预算结果 | 当前未提供时为0/— |

基地其他中包含按比例归集的实验室及制造体系费用，不得在利润公式中重复扣减。基地项目利润＝损益毛利润－基地质量－基地PMC－基地运营－基地其他－物流费－销售费用－管理费用－研发费用－其他损益＋其他收益，其中其他损益＝资产减值损失＋信用减值损失。该结果作为基地巴长考核数据。具体报表项编码应在指标字典中配置，但公式关系不得由前端临时改变。

基地项目利润率＝基地项目利润÷销售收入。原Excel中若存在“毛利润÷收入”的同名公式，不作为平台正式口径。

## 10.4 基地页面

1. **基地汇总看板**：全基地收入、毛利、利润、预算达成、趋势、排名、异常及亮点。
2. **单基地看板**：授权基地的当期/累计、预算/实际/GAP；普通业务按该基地配置显示型号或型号＋项目结构，零售、B品分别单列。
3. **基地损益表**：BY月份与BY基地两种展现，报表项一致；应包含其他收益行，即使当前无来源时显示0/—。
4. **基地指标树**：从考核利润下钻至收入、成本、费用及关键驱动因素。
5. **基地PVM**：普通业务按基地有效粒度计算；型号＋项目模式先合并同项目明细并提供型号小计，型号模式合并型号下全部项目；零售、B品分别按特殊业务类型汇总。
6. **预算占比表**：总部财经上传；基地财务只看名称字段包含其授权基地名称的数据。例如授权“义乌”时匹配B列包含“义乌”的记录。该规则只用于预算占比表分发，不用于正式基地归属计算。

## 10.5 基地权限

| 角色 | 可查看范围 | 明细 | 导出 | 配置 |
|---|---|---|---|---|
| 总部财经 | 所有基地，看板＋损益＋明细＋底稿 | 是 | 是 | 查看＋编辑 |
| 总部运营 | 所有基地，已发布看板＋损益＋PVM＋指标树＋非财经指标 | 否 | 是（仅已发布汇总） | 只读 |
| 基地财经 | 对应基地，看板＋损益＋明细＋底稿 | 是 | 是 | 查看＋编辑授权范围 |
| 基地巴长 | 对应基地，看板＋损益计算结果 | 否 | 否 | 查看 |
| 基地运营 | 对应基地，仅损益计算结果 | 否 | 否 | 查看 |

## 10.6 非财经指标分析（电芯优率）

### 10.6.1 功能定位

非财经指标作为统一经营分析平台中的独立分析菜单，与财经损益、PVM和经营总览共用批次、权限、映射、审计和发布能力，但不参与财经利润、成本、PVM或经营总览指标的计算。首期实现“电芯优率”目标值与实际值对比，后续可在同一数据对象规范下扩展其他非财经指标。

### 10.6.2 数据导入与批次

1. 总部/授权财经用户在“月度数据导入—非财经指标”中上传文件；非财经数据与基地收入成本、期间费用等财经数据分开选择和校验。
2. 上传模板采用长表结构：期间、基地、拉线、电芯型号、类目、目标/实际、指标值。若来源仍为按月份展开的宽表，系统在导入适配层转换为长表后再校验；页面和接口只保存标准长表。
3. 同一期间的非财经指标数据采用整期覆盖，重传生成新文件版本，旧版本可追溯但不参与计算；基础映射仍采用增量维护。
4. 系统检查期间完整性、目标/实际成对情况、重复业务键、数值范围、类目有效性和电芯型号是否可匹配巴长。问题分为阻断项和警告项，未匹配不得静默丢失。
5. 财经点击“开始计算”后，系统生成非财经指标结果版本；非财经指标不要求等待财经损益计算完成，但结果版本应绑定同一月度批次和权限快照。

### 10.6.3 巴长映射与权限

1. 巴长映射复用“销售项目映射”中的“电芯型号—巴长—巴长工号”字段，不新增单独的非财经巴长映射表。
2. 匹配键仅为电芯型号；基地、拉线、类目不参与巴长归属匹配。一个巴长可关联多个电芯型号，同一电芯型号不得归属多个有效巴长。
3. 总部财经可查看所有基地、拉线、型号和巴长数据；基地财经只能查看授权基地；非财经巴长只能查看映射至本人巴长工号的电芯型号数据。
4. 基地/巴长权限采用服务端行级过滤，不能通过修改页面参数、导出参数或接口参数绕过；无映射数据进入未匹配清单，不自动归入其他巴长。

### 10.6.4 计算口径

| 结果项 | 规则 |
|---|---|
| 目标值 | 取同一期间、基地、拉线、电芯型号、类目且类型为“目标值”的指标值 |
| 实际值 | 取同一期间、基地、拉线、电芯型号、类目且类型为“实际值”的指标值 |
| 差额 | 实际值－目标值；正数表示超过目标，负数表示低于目标 |
| 达成率 | 实际值÷目标值；目标值为0时显示“—”，不得产生除零错误 |
| 多行处理 | 相同业务键重复时阻断；不同基地/拉线分别保留，不跨基地简单平均 |
| 巴长汇总 | 一期按电芯型号明细展示并汇总“达标型号数/未达标型号数”；不对比例直接做简单平均，若后续需加权汇总，必须补充分子分母或加权规则 |

### 10.6.5 页面设计

非财经指标页面至少包含：

- 筛选条件：期间、基地、巴长、拉线、类目；巴长下拉选项根据当前用户权限过滤。
- 汇总卡片：有效型号数、达标型号数、未达标型号数、未匹配型号数。
- 明细表：巴长、基地、拉线、电芯型号、类目、目标值、实际值、差额、达成率、状态、来源批次。
- 状态：达标、未达标、仅目标、仅实际、未匹配、目标为0。仅目标/仅实际为正常数据状态，不作为技术故障。
- 说明：明确“巴长仅按电芯型号匹配；基地仅用于展示和权限过滤；一个巴长可关联多个电芯型号”。

### 10.6.6 异常与修正

- 电芯型号无法匹配巴长：展示未匹配数量、金额/指标值、来源行和处理入口；财经可补充通用映射后重新计算。
- 同一电芯型号匹配多个有效巴长：阻断非财经指标结果发布，要求先消除冲突。
- 指标值为空、超出合理比例范围或目标/实际类型非法：文件行进入错误清单；不影响已通过校验的其他期间批次。
- 忽略未匹配仅代表不纳入巴长结果，不得删除原始行；系统保留忽略人、时间和理由。

# 13. PVM因素分析设计

## 13.1 变量定义

对每个正式分析粒度定义：实际单价`Pa`、预算单价`Pb`、实际电量`Qa`、预算电量`Qb`、实际单位成本`Ca`、预算单位成本`Cb`、实际单位毛利`Ma=Pa-Ca`、预算单位毛利`Mb=Pb-Cb`、预算收入占比`Sb`、预算加权单位毛利`M̄b`。

## 13.2 收入PVM

| 因素 | 公式 |
|---|---|
| 价格影响 | `(Pa - Pb) × Qa` |
| 销量影响 | `(ΣQa × Sb - Qb) × Pb` |
| 结构影响 | `(Qa - ΣQa × Sb) × Pb` |

价格影响＋销量影响＋结构影响＝实际收入－预算收入。

## 13.3 毛利PVM

| 因素 | 公式 |
|---|---|
| 价格影响 | `(Pa - Pb) × Qa` |
| 销量影响 | `(Qa - Qb) × M̄b` |
| 成本影响 | `-(Ca - Cb) × Qa` |
| 结构影响 | `(Qa - ΣQa × Sb) × (Mb - M̄b)` |

毛利各因素合计＝实际产品毛利－预算产品毛利。成本影响继续拆分为材料成本、材料损耗和非材料成本，其中非材料成本包括人工、外协、制造变动和制造固定。

## 13.4 三视角匹配

- 基地普通业务：由基地配置决定使用“收入计算基地＋电芯型号＋客户项目改”或“收入计算基地＋电芯型号”；型号＋项目模式先按项目合并，并可汇总为型号小计。
- 基地特殊业务：客户项目改为零售、B品时，分别按“收入计算基地＋特殊业务类型”匹配，不考虑电芯型号。
- 产品线：产品线＋客户项目＋客户简称改2＋电芯型号；正式占比按完整产品线范围计算。
- 事业部：事业部＋客户项目＋电芯型号；项目小计不重算占比。

用户可对期间、基地、项目、客户等单选或多选。筛选只改变展示范围时，必须明确区分“正式占比”与“当前筛选占比”；一期正式结果始终使用完整授权分析范围的正式占比，避免单项目筛选导致结论失真。

## 13.5 PVM页面呈现

PVM页顶部提供期间、当期/累计、视角、基地/产品线/事业部、客户和项目的单选或多选条件。普通基地结果区按该基地粒度模式展示：型号模式按电芯型号展示，型号＋项目模式按型号展开项目并提供型号小计。基地零售、B品不按型号拆分，分别形成特殊业务汇总。产品线和事业部仍按各自既定粒度展示。指标至少包括电量、销售收入、销售成本、毛利、材料成本、材料损耗、人工、外协、制造变动、制造固定的预算、实际、GAP，以及收入PVM、毛利PVM和成本拆分因素。

页面同时提供：总体桥接图、因素明细表、正常特殊场景标签、未勾稽差异区和导出。筛选条件变化后，页面必须注明当前显示采用“正式占比”还是“仅筛选汇总”；不得在前端临时重算并覆盖已发布PVM。

## 13.6 PVM异常规则

- 实际或预算电量为0时，单价/单位成本显示“—”，总额仍参与桥接；因素归入“新增业务”“未发生业务”或系统定义的零量规则。
- 无预算有实际、无实际有预算属于正常业务场景，需单独标识但不作为技术错误。
- 型号为空时保留为“型号为空”组；若无法形成正式匹配粒度，PVM发布前由财经确认处理。
- PVM桥接差异不为0时，阻断发布并展示差异来源。

# 14. 看板、损益表、指标树及明细查询

## 14.1 公共查询条件

视角、分析对象、年度、月份、口径（当期/累计）、场景（实际/预算/GAP）、币种/单位。基地视角增加粒度模式和特殊业务类型；粒度模式只用于说明当前结果口径，不允许查询时临时切换并重算。系统默认当前已发布期间和用户主数据范围；无权限的筛选值不返回给前端。

## 14.2 经营看板

看板至少包含：核心KPI卡片、预算达成、同比/环比（有历史数据时）、月度趋势、结构分布、排名、异常项目、亮点、风险及下钻入口。颜色规则应统一：收益类正向为有利、成本费用类正向为不利，不使用单纯“正数红/负数绿”。

## 14.3 损益表

- 行为报表项，列为实际、预算、GAP、达成率；支持当期和累计。
- 产品线/事业部预算、实际、GAP应分别提供独立页签或视图，不把全年预算与月度实际强行拼成超宽大表。
- 支持按权限下钻至组成项及源明细；无明细权限者只查看汇总。
- 每个报表项提供口径说明、数据来源、公式、更新时间和结果版本。

## 14.4 指标树

以考核利润为根节点，向下展开毛利、收入、成本、费用、减值等。节点显示实际、预算、GAP、贡献度和有利/不利。点击节点可跳转至对应PVM、费用或明细分析。

## 14.5 明细查询

明细页面按数据对象和授权范围查询，展示标准值、归属结果、映射规则、分摊链路、调整记录和原文件定位。页面不得直接修改源明细；需要纠正时引导至重传、配置修复或人工调整。

## 14.6 导出

- 导出内容与用户当前权限和筛选条件一致。
- 文件包含结果版本、导出人、导出时间、筛选条件和口径说明；基地导出同时标明粒度模式和特殊业务类型。
- 大文件异步生成，完成后在站内消息通知；下载链接限时有效。
- 导出操作记录文件名、范围、行数和人员。

## 14.7 页面级交互要求

1. **所有结果页**顶部固定展示期间、视角、口径、结果版本、发布时间和数据更新时间；基地页面同时展示本次结果采用的粒度模式。
2. **筛选器**只返回用户有权范围；切换当期/累计后，月份保留但重新查询。
3. **指标卡**点击进入对应组成项，不允许跳到无权限明细。
4. **表格**支持冻结首列、按金额/达成率排序、列显隐和口径悬浮说明。
5. **异常标识**区分数据质量、经营异常和系统错误，不使用同一红色提示混淆。
6. **未发布状态**对经营角色不显示草稿数字；财经角色可进入预览并明确标注“未发布”。
7. **无数据**显示“本期无数据/未上传/无权限/计算未完成”之一，不以空白页代替。
8. **刷新**查询已持久化结果，不触发后台重新计算。

# 15. AI经营分析

## 15.1 定位

AI是经营结果解释助手，不是财务计算引擎。AI读取规则引擎已经生成并通过校验的指标、趋势、PVM、费用分类和授权明细，不直接读取未经校验的原始Excel，不修改正式结果。基地AI上下文必须携带该结果版本的粒度模式，并将零售、B品作为两个独立特殊业务类型，避免按普通型号口径解释。

## 15.2 生成方式

财经在已确认或已发布结果上点击“生成AI分析”，选择视角、范围、期间和当期/累计。系统组装结构化上下文后调用公司本地AI。生成任务异步执行，失败可重试。

## 15.3 一期固定输出结构

1. 经营总述。
2. 未达标事项。
3. 经营亮点。
4. 原因线索。
5. 风险提示。
6. 行动建议。

不强制每条结论在正文显示指标值、差异金额和下钻依据，但系统必须保存本次AI读取的数据范围、结果版本、指标快照、提示词版本、模型版本及生成时间，便于复核。

## 15.4 审核与分发

- 总部财经可查看全部AI草稿；基地财经只查看本基地草稿；产品线/事业部财务BP只查看其授权范围草稿。
- 其他人员只能看到经财经确认并分发的AI分析，以及其本身有权查看的看板/损益结果。
- 草稿支持财经编辑、重新生成、确认、撤回和分发。重新生成不覆盖旧草稿。
- 集团/总部财经决定最终分发对象和时间。

## 15.5 AI安全

- 仅调用公司批准的本地模型及网关，不将经营数据发送至公网模型。
- 组装上下文前先执行服务端权限过滤。
- 提示词明确禁止虚构数据、改变财务口径、将相关性表述为确定因果。
- 输出标注“AI辅助分析，需财经复核”。

# 16. 数据修正、重算、确认与发布

## 16.1 一期修正路径

| 问题类型 | 首选处理 | 一期补充手段 |
|---|---|---|
| 源明细错误 | 修正Excel后整期重传 | 无 |
| 映射错误/缺失 | 维护映射后重算 | 可暂时忽略并归入未映射，但不得影响必须归属项发布 |
| 分摊比例错误 | 修正比例后重算 | 无 |
| 财经结果型数据错误 | 重新上传结果表 | 无 |
| 临时口径、短期无法改源 | 简易人工调整 | 需填写原因、附件/依据、对象、报表项和金额 |

## 16.2 简易人工调整

一期提供“调整单”，不做复杂工作流。字段至少包括：期间、视角、分析对象、实际/预算、报表项、调整金额、正负方向、原因、依据附件、录入人、录入时间、是否有效。只有总部财经及授权财务BP可维护；调整在计算链路中作为独立数据层叠加，并在报表项下钻中单列，不直接修改原始数据。

调整金额必须参与总额和跨视角勾稽。若同一事项同时影响基地和产品线/事业部，财经需分别指定影响范围，系统不得自行跨数据集复制。

## 16.3 结果确认

计算成功后生成计算报告，至少包含：数据版本、配置快照、记录数、未匹配金额、排除金额、分摊校验、损益勾稽、PVM勾稽、调整项和警告项。财经确认前必须逐项查看；存在阻断项时确认按钮不可用。

## 16.4 发布

- 发布对象为“期间＋视角＋结果版本＋数据范围”。
- 发布后按用户权限立即可见；可以选择统一发布时间。
- 重新发布新版本时，旧版本标记已替代但仍可追溯。
- 允许撤回尚未被新版本替代的发布结果；撤回需说明原因并通知已分发对象。
- 产品线/事业部结果在初始化时配置最终确认人；一期可将吕宏设置为确认人，但不得在代码中写死姓名。

## 16.5 待办与通知

系统对以下事件生成站内待办：必需数据未上传、校验失败、映射未匹配、计算失败、结果待确认、发布完成、发布撤回、AI草稿待确认。待办包含期间、视角、责任角色、截止时间、问题数量和直达链接。通知只提示事项，不在消息正文暴露经营数据。

# 17. 权限、安全与审计

## 17.1 权限模型

权限＝功能权限 × 数据视角 × 数据范围 × 数据层级 × 操作权限。

- 功能：看板、损益、PVM、明细、配置、计算、发布、AI、审计。
- 视角：基地、产品线、事业部。
- 范围：具体基地/产品线/事业部，可多选。
- 层级：汇总、结果、标准明细、原始底稿。
- 操作：查看、上传、编辑、导出、确认、发布、分发。
- 非财经指标额外使用“巴长工号＋电芯型号”行级范围；不新增独立巴长映射表，直接复用通用销售项目映射中的巴长字段。基地只作为非财经页面的筛选和基地财务授权条件，不参与巴长归属匹配。

所有数据过滤必须在服务端执行，前端隐藏菜单不能代替权限控制。

## 17.2 权限变更

用户权限通过初始化模板导入，也支持页面维护。新增、变更、失效均记录操作人和时间。用户失效后立即不能访问；历史操作日志仍保留。

## 17.3 审计范围

系统记录登录、上传、下载、配置修改、忽略异常、人工调整、计算、重试、确认、发布、撤回、导出、AI生成/编辑/分发及权限变更。日志至少包含操作人、工号、时间、对象、前值、后值、IP/终端信息和结果。

## 17.4 数据安全

- 文件存储加密，下载采用授权校验和限时链接。
- 数据库按最小权限访问，生产环境禁止开发人员直接修改结果表。
- 敏感日志不得记录完整财务明细或上传文件内容。
- 备份与恢复范围包括源文件、配置、结果、权限及审计日志。

# 18. 接口、任务及技术实现建议

## 18.1 一期接口边界

一期仅有文件上传/下载、本地AI调用、统一身份认证（若公司平台具备）及站内通知。ERP等业务系统接口预留数据对象编码和API层，不在一期开发范围内。

## 18.2 推荐服务划分

| 服务 | 职责 |
|---|---|
| 文件与模板服务 | 模板版本、上传、病毒扫描、文件存储、解析 |
| 数据质量服务 | 字段、行、映射、跨表、完整性校验 |
| 配置服务 | 映射、分类、分摊、汇率、指标和权限范围 |
| 计算服务 | 标准化、映射、分摊、损益、PVM、勾稽 |
| 报表服务 | 查询、下钻、导出、结果版本 |
| 工作流服务 | 批次状态、确认、发布、撤回、通知 |
| AI编排服务 | 上下文组装、模型调用、提示词、草稿及分发 |
| 审计服务 | 关键操作留痕和查询 |

## 18.3 关键任务

- 文件解析、数据校验、计算、导出和AI生成均采用异步任务。
- 任务应支持进度、心跳、超时、失败原因、人工重试和幂等。
- 计算任务以`期间＋数据集＋源版本集合＋配置快照哈希`作为幂等判断依据；相同输入重复执行可复用结果或显式生成新版本。
- 不允许部分结果写入后被当作成功版本；采用暂存表/事务或版本切换机制。

## 18.4 推荐API清单

| API组 | 典型能力 |
|---|---|
| `/templates` | 查询、下载有效模板 |
| `/batches` | 创建期间批次、查看完整性和状态 |
| `/files` | 上传、校验、预览、切换生效版本 |
| `/issues` | 查询、处理、忽略、导出异常 |
| `/mappings` | 维护销售项目、库存、费用分类等配置 |
| `/allocations` | 维护分摊比例、检查100% |
| `/base-grain-configs` | 维护各基地分析粒度、校验唯一有效配置并查询影响范围 |
| `/calculations` | 发起、查询、重试计算任务 |
| `/results` | 查询损益、指标、PVM、明细和版本 |
| `/adjustments` | 新增、失效、查询调整项 |
| `/publications` | 确认、发布、撤回、查看历史 |
| `/ai-analyses` | 生成、编辑、确认、分发AI分析 |
| `/permissions` | 用户、角色和范围维护 |
| `/audit-logs` | 审计查询和导出 |

## 18.5 可观测性与问题定位

- 每次上传、校验、计算、导出和AI任务生成全局追踪号。
- 日志按任务阶段记录开始、结束、处理行数、异常行数和耗时，不记录无关敏感字段。
- 计算失败需区分数据错误、规则错误、资源不足和程序异常，并返回可执行的处理建议。
- 运维页面可按追踪号查看任务链路和安全重试，不允许直接改数据库“修结果”。

# 19. 非功能要求

## 19.1 性能

- 常规看板首屏在正常公司网络下目标3秒内返回；复杂下钻目标5秒内。
- 10万行以内单文件上传后，系统应即时返回接收成功，后台解析和校验进度可见。
- 月度全量计算目标30分钟内完成；若超过，应显示具体阶段和预计剩余任务，而非前端持续等待。
- 常规汇总导出5分钟内完成；大文件异步处理。

## 19.2 可用性与恢复

- 月结及经营分析高峰期核心功能可用性目标99.5%。
- 计算、发布接口必须幂等；网络重试不得重复生成有效结果。
- 每日备份关键数据库和配置，源文件按公司策略备份；应具备按结果版本恢复和审计能力。

## 19.3 可维护性

- 报表项、指标名称、显示顺序、收益/成本属性、单位和说明由指标字典管理。
- 公式关系使用受控规则配置或后端版本化代码，不允许普通用户输入任意脚本。
- 日志以业务编号串联文件、批次、异常、计算、结果和发布，便于运维定位。

## 19.4 兼容与易用性

- 适配公司标准PC浏览器和1920×1080分辨率，常用页面不出现无意义横向滚动。
- 上传、异常和计算页面提供明确下一步提示。
- 所有状态、错误码和财务术语使用中文，并提供口径说明。

1. P0功能全部完成，无阻断级缺陷。

| UAT-052 | 巴长行级权限 | 登录不同巴长用户 | 只能查看映射至本人巴长工号的型号数据，不能通过筛选、导出或URL越权 |

| UAT-054 | 未匹配型号 | 导入不存在于通用映射的电芯型号 | 进入未匹配提醒并保留原始行，补充映射后可重算，不静默归属 |

| UAT-056 | 目标为0 | 目标值为0、实际值有值 | 达成率显示“—”，不产生除零错误 |
| UAT-057 | 重复键 | 同一期间、基地、拉线、型号、类目、目标/实际重复 | 行级校验阻断并提供重复行定位 |
| UAT-058 | 非财经与财务隔离 | 非财经指标导入和计算 | 不改变经营总览、损益、PVM和AI正式财务结果 |
| UAT-059 | 总部运营权限 | 登录总部运营角色并访问各分析页面 | 可查看全域已发布经营结果、PVM、指标树、非财经指标和已发布AI；不可进入月度导入、基础配置、指标库、用户/菜单管理或发布操作 |
| UAT-060 | 绝对 GAP 与 TOP | 同时准备金额影响大比例小、金额影响小比例大的对象 | KPI、表格和导出绝对 GAP 一致；TOP 按影响金额排序并区分有利/不利 |
| UAT-061 | 事业部基地×产品矩阵 | 同一事业部跨多个基地和产品 | 行列合计与同口径事业部汇总一致，单元格可下钻且不越权 |
| UAT-062 | 经营分析利润口径 | 数据同时包含研发、运营、资产/信用减值 | 矩阵口径按确认规则剔除，完整损益仍保留原项目，二者标签清晰 |
| UAT-063 | YU 趋势 | 提供连续12个月及不足12个月两组数据 | 按确认公式计算；不足月份不补造；指标卡、趋势和明细一致 |
| UAT-064 | 线体单位制造费用 | 覆盖正常、零电量、有费无量、共线分摊 | 汇总按总费用÷总Wh计算，异常场景单列，分子分母可追溯 |
| UAT-065 | FC 多版本 | 同一基准月导入两个FC版本并指定一个正式版 | 仅正式采用版默认展示；历史版可查且不覆盖已发布结果 |
| UAT-066 | 三场景对比 | 同时存在ACT、BGT、FC | ACT-BGT、ACT-FC、FC-BGT按同一版本和范围计算，导出标明FC版本 |
| UAT-067 | 风险一页纸 | 同一风险触发多个阈值并包含受限明细 | 风险合并展示并保留触发依据；页面与PDF一致且不泄露未授权明细 |
| UAT-068 | 单位毛利瀑布 | 覆盖正常、零量、新增和退出业务 | 起点＋因素＝终点；未分解差异单列；异常场景不强算单位值 |

| UAT-070 | 产品线三级下钻 | 准备完整层级、未映射和无权限对象 | 各级汇总勾稽，筛选上下文保持，未映射单列且无越权 |
| UAT-071 | PVM跨维筛选 | 按基地、产品、客户、项目组合筛选 | 正式PVM分母不被页面筛选改写，正式结果与筛选汇总有明确标识 |
| UAT-072 | 费用/研发专题 | 运营费用、研发提单、基地科目均含可追溯样本 | 专题金额与损益/费用事实一致，映射失败可识别，提单不直接改写正式费用 |

## 20.3 数据验收样本

# 22. 经营看板优化增量需求（2026-09-21）

## 22.1 来源、状态与适用原则

本章整合产品线财经于2026年9月21日提出的经营分析看板优化需求。原始会议纪要和原需求文件已遗失，当前依据已恢复摘要及现有V1.2、Demo和开发清单重建。原摘要称共有14个讨论点，其中8个P0、6个P1；目前可确认7个P0和6个P1，第8个P0保留缺口，不臆测。

完整重建底稿见 `经营分析看板优化需求_20260921.md`。本章作为V1.3主规格的一部分，约束开发和测试；凡标记“待确认”的口径，在业务书面确认前只允许制作原型，不得进入正式计算和发布。

## 22.2 与既有口径的关系

1. V1.2定义的完整损益、三视角独立规则、正式PVM粒度、权限、批次、发布和审计原则继续有效。
2. 事业部“基地×产品”矩阵新增的经营分析利润口径明确剔除研发、运营及资产/信用减值，但不得覆盖完整损益口径；其余纳入项待财经确认。
3. FC是ACT/BGT之外的新场景。一期只纳入FC结果导入、校验、版本、发布、查询、对比和导出，不建设在线预测编制、协同填报或自动预测模型。
4. 风险一页纸的正式风险由确定性阈值或财经确认产生；AI只能补充原因线索和文字摘要。
5. 单位类、比率类指标跨对象汇总时，应按汇总后的分子/分母重新计算，不得简单平均。

## 22.3 P0需求

### P0-D01 KPI和表格增加绝对GAP及TOP榜

- KPI、损益、明细和专题表在百分比GAP外同步展示绝对值GAP。
- 支持ACT-BGT；FC上线后支持ACT-FC，是否展示FC-BGT由业务确认。
- TOP榜按影响金额排序，分别展示有利和不利事项；点击后进入同期间、同场景、同结果版本的下钻页面。
- 收益类与成本费用类分别判断有利/不利；分母为0时比例显示“—”，绝对GAP仍展示。
- TOP数量配置化；页面、接口和导出使用同一结果。

### P0-D02 事业部“基地×产品”交叉矩阵

- 一个轴为基地、另一个轴为产品，支持行列互换、合计、排序、颜色提示和单元格下钻。
- 指标至少考虑收入、毛利、毛利率及经营分析利润；展示ACT、BGT、绝对/百分比GAP，FC上线后支持FC。
- 经营分析利润暂明确剔除研发费用、运营费用、资产减值和信用减值；完整公式待财经确认。
- 行合计、列合计必须与事业部同口径结果一致；未映射、无数据、零值和无权限状态分别处理。

### P0-D03 YU指标卡及12个月趋势

- 增加YU指标卡，展示当月值、目标/预算值、绝对GAP、百分比GAP和趋势方向。
- 展示最近12个自然月趋势；历史不足12个月时只展示已有月份。
- YU全称、公式、单位、分子分母、汇总方式和ACT/BGT/FC来源均待确认；确认前不得进入正式计算。

### P0-D04 线体单位制造费用专项分析

- 核心指标为线体单位制造费用（元/Wh），暂按“线体制造费用金额÷对应电量（Wh）”设计。
- 支持ACT/BGT/FC、绝对/百分比GAP、12个月趋势、线体排名和异常TOP。
- 可下钻制造费用类别、会计科目和来源明细；至少区分变动和固定制造费用。
- 必须确认线体主数据、费用范围、Wh分母、共线分摊和零量规则。
- 汇总单位费用按总费用÷总电量计算，不平均各线体单位值。

### P0-D05 FC滚动预测与BGT/ACT三场景并列

- 场景维度扩展为ACT/BGT/FC，支持ACT-BGT、ACT-FC、FC-BGT差异。
- FC包含版本号、预测基准月、覆盖期间、状态、上传人、发布时间和正式采用标识。
- 同一分析基准只允许一个正式采用版本；历史版本保留并可追溯。
- 无正式FC时明确提示，不使用BGT或历史FC静默替代。
- 看板、损益、PVM及专题是否支持FC必须逐模块登记，禁止默认视为全量覆盖。

### P0-D06 独立“一页风险提示”视图及PDF

- 页面至少包含范围和版本信息、风险摘要、风险TOP、风险分布、财经确认说明及口径信息。
- 风险来源可包括不利绝对GAP、达成率、连续恶化、单位成本、亏损、未匹配和人工标记。
- 风险阈值配置化并版本化；重复风险合并展示并保留全部触发依据。
- 支持一页打印和PDF导出；内容继承当前权限、筛选条件和已发布结果版本。

### P0-D07 单位毛利GAP瀑布

- 支持“BGT单位毛利→影响因素→ACT单位毛利”；FC上线后支持“FC→ACT”。
- 单位毛利原则上为单位售价－单位成本，具体单位和分母待确认。
- 成本影响至少沿用材料、材料损耗、人工、外协、变动制费和固定制费。
- 起点＋因素＝终点；未分解差异单列，不得隐藏。
- 零量、新增和退出业务采用专门规则，不强算单位值。

### P0-D08 原会议第8项

内容遗失。补录或由需求负责人确认原实际仅有7项前，不估算、不开发、不计入完成率。

# 附录A：关键业务规则速查

1. 基地、产品线/事业部使用两套收入成本导入对象。
2. 产品线和事业部共用收入成本表，但按各自映射与口径计算。
3. 实际/预算分表，GAP由系统计算；累计为当年1月至所选月份。
4. 基地普通业务按基地配置为基地＋型号＋客户项目改或基地＋型号；产品线默认按型号；事业部按项目＋型号。
5. 基地按客户项目改将零售、B品分别汇总且不考虑型号；产品线和事业部按客户简称改2将零售、B品统一归为B品。
6. 三视角均不取财务费用；产品线不取销售/管理费用；事业部取三级费用明细中的销售/管理费用；基地仅宜昌取销售费用，管理费用和研发费用取三级费用明细并按费用匹配表归集。
7. 三视角减值均采用财经结果导入；基地当前没有信用减值数据时按0展示并记录本期无数据，不表述为制度性不取。
8. 闲置费用独立导入，产品毛利润不扣闲置费用，损益毛利润扣减闲置费用。
9. 映射及基地粒度配置无生效期间和版本，支持失效；计算结果保存配置快照。
10. 不计算、无效分类不纳入结果，但必须保留并可追溯。
11. 财务勾稽和PVM桥接容忍度为0。
12. AI不算账，只解释；财经点击生成、确认和分发。
13. 已发布结果不覆盖，新结果以版本替代。

# 附录C：源表核验结论

核验覆盖基地、产品线/事业部样表及三类基础配置表。基地表含21个Sheet、约1.16万条公式；产品线/事业部表含38个Sheet、约7.08万条公式，其中约2.62万条依赖外部工作簿，并存在引用、除零及数据错误。因此，平台运行时不得依赖原Excel公式或外链；有效公式仅用于口径取证，经财经确认后转为受控规则；所有源文件错误必须通过数据质量和勾稽机制暴露；减值、损耗等尚未系统化的复杂事项，一期导入结果，二期再治理上游逻辑。

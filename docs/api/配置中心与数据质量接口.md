# 配置中心与数据质量接口

## 1. 指标库

### 查询

`GET /api/v1/metrics?perspective=BASE&includeDisabled=true`

返回适用当前视角的指标定义。`includeDisabled=true` 用于配置维护页查看已停用指标。

### 新增或更新

`POST /api/v1/metrics`

```json
{
  "metricCode": "BASE_EXPENSE_TOTAL",
  "metricName": "基地费用合计",
  "applicablePerspective": "ALL",
  "unit": "CNY",
  "formulaExpression": "SUM(BASE_EXPENSE)",
  "displayOrder": 60,
  "enabled": true,
  "aiSummaryTemplate": "基地费用变化"
}
```

接口从认证主体读取操作人。公式字段只保存配置，正式计算仍需通过受控公式引擎解析，不允许前端直接执行任意脚本。

## 2. 映射关系

### 查询

`GET /api/v1/mappings?type=SALES_PROJECT&includeDisabled=true`

当前支持的映射类型：`SALES_PROJECT`、`INVENTORY`、`EXPENSE_RULE`、`FX_RATE`、`BASE_GRAIN`。

### 新增或更新

`POST /api/v1/mappings`

```json
{
  "type": "SALES_PROJECT",
  "matchKey": "客户简称|客户项目|电芯型号",
  "mappedValue": "事业部A|产品线A",
  "enabled": true
}
```

同一类型和匹配键采用更新语义；停用不删除历史记录。

### 停用

`POST /api/v1/mappings/disable`

```json
{
  "type": "SALES_PROJECT",
  "matchKey": "客户简称|客户项目|电芯型号"
}
```

## 3. 批次数据质量摘要

`GET /api/v1/batches/{batchNo}/quality`

接口需要认证，且以批次视角对应的数据集目录为判断范围。示例：

```json
{
  "code": "OK",
  "data": {
    "batchNo": "BATCH-202608-BASE-001",
    "perspective": "BASE",
    "status": "BLOCKED",
    "totalDatasetCount": 5,
    "requiredDatasetCount": 3,
    "presentRequiredDatasetCount": 2,
    "validRequiredDatasetCount": 1,
    "issueCount": 4,
    "missingDatasetCodes": ["BASE_ACT_EXPENSE"],
    "invalidDatasetCodes": ["BASE_ACT_INC_COST"],
    "datasets": []
  }
}
```

`READY` 仅表示必需数据集均存在且校验通过，不代表经营口径已经完成财经复核；未匹配、排除金额、勾稽差异和人工确认仍由后续质量规则补充。

## 4. 基础配置文件上传

基础配置与月度业务数据使用独立任务号和入口。

1. 创建配置导入任务：`POST /api/v1/config/imports`
2. 上传文件：`POST /api/v1/config/imports/{taskNo}/upload`，使用 `multipart/form-data` 的 `file` 字段。
3. 查询任务：`GET /api/v1/config/imports/{taskNo}`。

上传成功后文件进入受控导入文件存储，任务状态为 `VALIDATING`；继续调用校验接口后，系统完成工作表、标题重复、空标题和空数据行等结构校验，并将任务更新为 `VALID` 或 `INVALID`。当前版本尚不按配置类型写入指标/映射仓储，不将结构校验通过误认为配置已生效。

# 配置中心与数据质量接口

## 1. 指标库

### 查询

`GET /api/v1/metrics?perspective=BASE&includeDisabled=true`

返回适用当前视角的指标定义。`includeDisabled=true` 用于配置维护页查看已停用指标。

### 新增或更新

`POST /api/v1/metrics`

```json
{
  "metricCode": "BASE_EXPENSE_TOTAL",
  "metricName": "基地费用合计",
  "applicablePerspective": "ALL",
  "unit": "CNY",
  "formulaExpression": "SUM(BASE_EXPENSE)",
  "displayOrder": 60,
  "enabled": true,
  "aiSummaryTemplate": "基地费用变化"
}
```

接口从认证主体读取操作人。公式字段只保存配置，正式计算仍需通过受控公式引擎解析，不允许前端直接执行任意脚本。

## 2. 映射关系

### 查询

`GET /api/v1/mappings?type=SALES_PROJECT&includeDisabled=true`

当前支持的映射类型：`SALES_PROJECT`、`INVENTORY`、`EXPENSE_RULE`、`FX_RATE`、`BASE_GRAIN`。

### 新增或更新

`POST /api/v1/mappings`

```json
{
  "type": "SALES_PROJECT",
  "matchKey": "客户简称|客户项目|电芯型号",
  "mappedValue": "事业部A|产品线A",
  "enabled": true
}
```

同一类型和匹配键采用更新语义；停用不删除历史记录。

### 停用

`POST /api/v1/mappings/disable`

```json
{
  "type": "SALES_PROJECT",
  "matchKey": "客户简称|客户项目|电芯型号"
}
```

## 3. 批次数据质量摘要

`GET /api/v1/batches/{batchNo}/quality`

接口需要认证，且以批次视角对应的数据集目录为判断范围。示例：

```json
{
  "code": "OK",
  "data": {
    "batchNo": "BATCH-202608-BASE-001",
    "perspective": "BASE",
    "status": "BLOCKED",
    "totalDatasetCount": 5,
    "requiredDatasetCount": 3,
    "presentRequiredDatasetCount": 2,
    "validRequiredDatasetCount": 1,
    "issueCount": 4,
    "missingDatasetCodes": ["BASE_ACT_EXPENSE"],
    "invalidDatasetCodes": ["BASE_ACT_INC_COST"],
    "datasets": []
  }
}
```

`READY` 仅表示必需数据集均存在且校验通过，不代表经营口径已经完成财经复核；未匹配、排除金额、勾稽差异和人工确认仍由后续质量规则补充。

## 4. 基础配置文件上传

基础配置与月度业务数据使用独立任务号和入口。

1. 创建配置导入任务：`POST /api/v1/config/imports`
2. 上传文件：`POST /api/v1/config/imports/{taskNo}/upload`，使用 `multipart/form-data` 的 `file` 字段。
3. 查询任务：`GET /api/v1/config/imports/{taskNo}`。
4. 查询问题：`GET /api/v1/config/imports/{taskNo}/issues`。

上传成功后文件进入受控导入文件存储，任务状态为 `VALIDATING`；继续调用校验接口后，系统完成工作表、标题重复、空标题和空数据行等结构校验。校验通过后，`METRIC_DEFINITION` 会按指标编码增量更新指标库；销售项目、库存、费用分类/分摊、汇率、基地粒度等映射类型会按“类型＋匹配键”增量更新映射仓储。文件内重复键、必填字段缺失或应用失败会追加问题并将任务置为 `INVALID`，本次任务不写入任何指标/映射记录。`USER_PERMISSION` 当前只做留存和结构校验，必须经过后续管理员授权流程后再应用。只有校验和应用均成功才会更新为 `VALID`，前端会明确提示“校验并应用通过”。

### 4.1 配置文件标准字段

指标库真实模板 `27-指标库配置.xlsx` 的数据录入列为：`指标编码`、`指标名称`、`计算公式`、`适用视角`、`单位`、`展示顺序`、`是否有效`、`AI简析模板`。应用器兼容历史接口字段 `formulaExpression`、`公式`、`指标公式`，但真实模板字段以 `计算公式` 为准；`展示顺序`和`是否有效`分别映射为指标的排序和启用状态。

21—26 号真实模板不使用通用的`匹配键`、`映射值`两列。应用器按配置类型读取模板业务字段，并将业务键和输出字段按固定列序保存到现有映射仓储：

| 配置类型 | 业务键 | 输出字段 | 映射类型 |
| --- | --- | --- | --- |
| 21 销售项目映射 | `客户简称`、`客户项目`、`电芯型号` | `产品线`、`事业部`、`B品标识`、`备注`、`巴长`、`巴长工号` | `SALES_PROJECT` |
| 22 库存档案映射 | `物料编码` | `电芯型号`、`产品类型`、`产品线`、`事业部`、`分摊比例`、`备注` | `INVENTORY` |
| 23 费用分类映射 | `三级费用编码`，为空时使用`三级费用名称` | `费用分类`、`基地`、`产品线`、`事业部`、`备注` | `EXPENSE_RULE` |
| 24 费用分摊配置 | `期间`、`费用项目`、`来源基地`、`目标基地` | `分摊比例`、`备注` | `EXPENSE_RULE` |
| 25 汇率配置 | `期间`、`基地`、`币种` | `汇率`、`换算方向`、`备注` | `FX_RATE` |
| 26 基地分析粒度配置 | `基地`、`电芯型号` | `分析粒度`、`备注` | `BASE_GRAIN` |

业务键和输出字段使用 `|` 按模板列序拼接，`是否有效`映射为仓储的启用状态。旧版包含`匹配键`、`映射值`的通用文件仍兼容；系统不根据文件名猜测业务类型。

28 号用户权限模板按真实列执行结构和必填值校验，文件留存到配置导入任务，但当前不会自动写入权限仓储，必须经过后续管理员授权流程。

问题接口返回每条问题的行号、字段名、错误编码、错误说明和原始值；问题记录与任务号绑定，重新校验同一任务时会整体替换，不保留过期问题。

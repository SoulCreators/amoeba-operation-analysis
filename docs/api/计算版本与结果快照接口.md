# 普通计算版本与历史结果

适用：db Profile，V035 及以后。实现边界与业务阻断见 [计算可靠性报告](../reports/2026-10-22-calculation-reliability.md)。

## 计算与生命周期

已有 `POST /api/v1/calculations` 请求不变，继续以 Principal 为操作者。成功生成独立版本，versionNo 使用批次内 R1、R2…，以 batchNo＋versionNo 定位。调用方应将版本号视为不透明字符串。事务失败不切换当前结果；并发计算同一批次由数据库锁互斥。

成功计算只表示候选结果已保存，不表示发布门禁通过。确认及发布接口保持原路径，两者均读取本版本持久化勾稽报告，缺证据、非零差异或 BLOCKED 均拒绝。目前每个普通版本保留 `PVM_FORMAL_GRAIN` 阻断；零量还会增加 `PVM_ZERO_VOLUME`。没有放宽金额容忍度或批准待确认财务规则。

## 指定历史版本结果

`GET /api/v1/calculations/{batchNo}/versions/{versionNo}/result`

无请求体；例如 `/api/v1/calculations/BATCH-001/versions/R1/result`。响应沿用 `ApiResult<CalculationResult>`，包含 batchNo、perspective、versionNo、status、生命周期时间与操作者、results、facts。results 执行 scope 过滤，facts 另执行明细权限过滤；事实来自该版本输入快照。金额为十进制数，不使用客户端计算替代服务端结果。

需要已认证 Principal、历史查看权限、结果状态可见权限及对应 scope 权限。匿名为 HTTP 401，无历史/范围权限为 HTTP 403；不存在或无范围权限统一拒绝。不会将不存在的历史版本回退为当前版本。local 存储无持久化历史能力，明确返回业务失败。

已有版本头列表接口 `GET /api/v1/calculations/{batchNo}/versions?perspective=BASE` 保持不变，其 snapshotId、jobId、hash、traceId 可供获授权的运维审计关联。完整输入 JSON、来源文件集合和勾稽表不通过本接口向普通查询者暴露。

## 数据保留与运维

计算快照是已有标准事实和当前配置上下文的冻结证据，配置使用标签为 `UPSTREAM_CONTEXT_ONLY`；不代表已经恢复导入发生时的配置。原始 Excel 长期留存仍由导入/存储域负责。具体验证、迁移、回退限制及剩余任务见报告，不应将接口可用等同于财经 UAT 完成。

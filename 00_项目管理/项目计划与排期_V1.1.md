# 阿米巴经营分析平台项目计划与排期

版本：V1.1  
编制日期：2026-09-17  
项目目标：2026年10月30日完成首期试运行，2026年11月13日正式上线

## 一、项目定位

本项目建设统一的阿米巴经营分析平台，首期解决“多表导入、口径配置、经营结果计算、三类视角分析、权限隔离和AI辅助分析”问题。平台不改变财经已确认的正式口径，不在一期重构收入成本核算逻辑，也不在一期接入ERP自动取数。

### 首期交付范围（MVP）

1. 国内基地及海外匈牙利、泰国数据导入。
2. 基地视角、产品线视角、事业部视角的预算、实际、GAP结果。
3. 基地汇总、单基地、PVM、指标树、经营结果明细查询。
4. 收入成本、费用、减值、闲置费用、预算占比等多类数据分表导入。
5. 销售项目、库存档案、费用分类、费用匹配、研发项目等映射配置。
6. 未匹配提醒、忽略留痕、计算批次、结果发布和重算记录。
7. 总部财经、基地财经、巴长、运营等角色的行级权限隔离。
8. 财经点击生成的AI分析草稿，固定输出经营总述、未达标、亮点、原因线索、风险和行动建议。

### 一期明确不做

- 不直接连接ERP、预算、PMS等源系统，全部通过人工导入。
- 不让大模型计算或改写正式财务结果；正式结果由确定性规则生成。
- 不重构财经现有收入成本核算、费用分摊和减值加工逻辑。
- 不建设通用低代码报表设计器；只支持已确认的页面和配置项。
- 不在一期实现复杂的自动纠错、自动调账和全量智能预测。

## 三、详细工作排期

### 阶段一：项目启动与基线冻结（9月17—24日）

| 工作项 | 产出 | Owner | 协同 |
|---|---|---|---|
| 确认首期范围和不做事项 | 范围基线 | 产品负责人 | 财经Owner、IT负责人 |
| 确认三视角维度和口径 | 业务规则清单 | 产品负责人 | 基地/产品线/事业部财经 |
| 冻结导入对象和字段 | 导入模板与字段字典 | 数据/产品 | 财经数据提供人 |
| 冻结指标、公式和勾稽关系 | 指标公式表 | 产品/财经 | 开发、测试 |
| 冻结用户角色与数据范围 | 权限初始化表 | 产品/财经 | IT应用架构 |
| 建立需求—开发—测试追踪关系 | 追踪矩阵 | 产品负责人 | 开发、测试 |

阶段出口：开发不得再依据截图直接开工；所有功能均能追溯到需求编号、字段或指标规则。

### 阶段二：数据底座与导入（9月28—10月9日）

| 工作项 | 主要内容 | 验收点 |
|---|---|---|
| 批次管理 | 月度批次、数据期间、导入状态、计算状态、发布状态 | 同一批次状态可查询、可重试 |
| 文件导入 | 各类数据分表上传，整期覆盖；映射和配置增量维护 | 格式错误可定位到行列 |
| 模板校验 | 表头、类型、必填、期间、重复、金额格式校验 | 错误不进入正式计算层 |
| 维度映射 | 销售项目、库存、费用分类、费用匹配、研发项目 | 未匹配记录形成清单 |
| 异常处理 | 财经可修正或忽略未匹配项 | 忽略需记录操作人、时间和金额 |
| 数据权限底座 | 按角色、视角、基地/产品线/事业部建立行级过滤 | API、页面、导出统一执行 |

阶段出口：使用脱敏样表完成一次“上传—校验—映射—异常查看—批次确认”穿行；如受公司假期影响，按实际工作日顺延。

### 阶段三：计算引擎与结果模型（10月12—16日）

| 工作项 | 主要内容 | 关键原则 |
|---|---|---|
| 标准化事实层 | 将预算、实际、费用、减值、闲置费用等统一为标准数据对象 | 保留原始数据和批次来源 |
| 维度派生 | 基地、财经修正项目、客户简称、电芯型号、产品线、事业部 | 映射关系可维护、可失效 |
| 损益计算 | 按已确认公式形成基地、产品线、事业部损益 | 有Excel公式优先按公式实现 |
| 费用归集 | 基地三级费用、总部费用分摊、实验室&制造体系比例 | 比例由财经配置，不需要审批 |
| 特殊业务 | 基地零售/B品分开；产品线/事业部统一归为B品 | 按视角加载不同规则包 |
| PVM | 按视角独立计算；支持当期/累计和组合筛选 | 验证差异必须为0 |
| 结果发布 | 计算完成后先由财经确认，再发布 | 发布结果不可被静默覆盖 |

阶段出口：计算结果、勾稽差异、输入批次、映射配置和操作日志可完整追溯。

### 阶段四：页面、权限与AI（10月19—28日）

| 工作项 | 主要页面/能力 | 验收点 |
|---|---|---|
| 基地汇总 | 当期/累计损益、预算对比、基地排名和异常提示 | 总部可看全量，基地按授权过滤 |
| 单基地 | 损益、费用、PVM、项目/型号明细 | 支持基地配置两种分析粒度 |
| 产品线/事业部 | 预算、实际、GAP分表及对应看板 | 共享源表、独立结果模型 |
| 指标树 | 指标层级、当期/累计、预算/实际/GAP | 与损益结果一致 |
| AI分析 | 财经点击生成草稿，固定六段输出结构 | 继承用户权限，人工审核发布 |
| 权限隔离 | 角色、数据视角、查看范围、明细、导出、配置维护 | 越权接口和导出均被拦截 |
| 审计追溯 | 导入、修正、忽略、计算、发布、AI生成记录 | 可按批次和用户查询 |

阶段出口：用四类角色执行权限穿行，并完成AI生成—草稿—确认—发布的完整闭环。

### 阶段五：联调、试运行、UAT与正式上线（10月29—11月13日）

1. 10月29日：开发自测、接口/API测试、权限测试、计算勾稽测试。
2. 10月30日：首期试运行，使用脱敏或测试数据完成完整业务穿行。
3. 11月2—6日：财经UAT，重点验证基地、产品线、事业部结果和权限隔离。
4. 11月6日晚：关闭P0/P1问题；P2问题形成上线后清单并明确责任人和日期。
5. 11月9—12日：上线准备、用户初始化、操作培训、回滚演练和发布评审。
6. 11月13日：正式上线，完成上线记录和首期版本归档。

## 四、项目角色与职责

| 角色 | 主要职责 | 说明 |
|---|---|---|
| 项目负责人/产品Owner | 范围、需求、优先级、跨部门协调、上线决策 | 负责把财经口径转成可开发规则 |
| 财经业务Owner | 指标、公式、映射、异常处理和结果确认 | 负责业务结果签字，不由IT替代判断 |
| 应用架构/后端 | 模块拆分、API、权限、任务、数据模型 | 负责可维护和可观测实现 |
| 数据/计算开发 | 导入、标准化、映射、公式、PVM和勾稽 | 规则必须单元测试和可追溯 |
| 前端开发 | 看板、筛选、明细、配置、异常和发布页面 | 页面权限与接口权限一致 |
| AI/分析开发 | AI上下文、提示词、草稿结构、审核发布 | AI只解释已发布/授权数据 |
| 测试/UAT | 功能、计算、权限、性能、回归和上线验收 | 测试用例关联需求编号 |
| 运维/发布 | 环境、日志、备份、部署、监控和回滚 | 首期需明确临时运维Owner |

## 五、项目运行机制

### 日常节奏

- 每日15分钟站会：昨天完成、今天计划、阻塞事项。
- 每日17:30更新：任务状态、问题等级、风险和次日计划。
- 每两天一次产品评审：只处理影响范围、口径或排期的决策。
- 每阶段出口评审：未通过不得直接进入下一阶段。

### 问题分级

| 等级 | 定义 | 处理要求 |
|---|---|---|
| P0 | 结果错误、越权、无法计算或阻断上线 | 当日响应，必须关闭或回滚 |
| P1 | 重要页面/规则不可用但有替代方案 | 24小时内给出修复计划 |
| P2 | 一般缺陷、体验或非核心优化 | 纳入上线后迭代清单 |

### 变更控制

9月24日范围冻结后，新增需求必须说明业务价值、影响范围、预计工时和对上线日期的影响。影响首期试运行或正式上线的新增需求原则上进入二期，不允许形成“边设计、边开发、边改口径”。

## 六、上线验收标准

1. 所有首期导入模板可上传、校验并形成批次记录。
2. 预算、实际、GAP及三视角核心损益结果可计算、可查询、可导出。
3. PVM及指标树与正式损益结果勾稽差异为0。
4. 未匹配数据必须提醒；忽略不阻断计算但必须留痕，不得静默丢失。
5. 四类角色执行权限穿行无越权：总部财经、基地财经、巴长、运营。
6. AI分析只能由财经点击生成，草稿和发布权限符合已确认规则。
7. 导入、配置、修正、计算、发布、导出和AI生成均有审计记录。
8. 财经人员可依据操作手册独立完成一次月度批次处理。

## 七、主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 财经公式或表格继续变化 | 造成返工和延期 | 9月24日冻结一期口径，变化进入变更评审 |
| 样表与真实数据格式不一致 | 导入失败 | 首期建立模板版本校验、错误行下载和人工修正入口 |
| 映射数据质量不足 | 结果不完整或错配 | 未匹配提醒、忽略留痕、控制总额校验和财经确认 |
| 权限范围名单不完整 | 越权或无法使用 | 上线前冻结姓名、工号、角色和授权对象 |
| 开发资源不足 | 核心功能无法按期完成 | 先做MVP主链路，非核心功能后置；每日暴露阻塞 |
| AI输出不稳定 | 误导业务判断 | AI只生成草稿，固定结构，财经确认后发布 |
| 上线窗口与月结、假期冲突 | UAT不足 | 10月30日先试运行，11月13日正式上线，预留一周问题收敛 |

## 八、项目成功定义

首期成功不是“页面全部做完”，而是财经可以在权限隔离下完成一次真实月度批次：导入数据、处理映射异常、点击计算、查看基地/产品线/事业部结果、生成AI草稿、确认并发布，同时任何结果都能追溯到输入文件、规则、配置和操作记录。
